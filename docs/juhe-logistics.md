# 聚合数据快递查询

## 后台配置

更新 api 云函数和小程序后，超级管理员进入「后台 → 系统设置 → 物流查询（聚合数据）」。选择聚合数据，打开查询开关，填写从聚合数据「个人中心 → 我的数据 → 常用快递查询」取得的 Key，点击「保存设置」。这与宠托师实名核验的 Key 分开保存。

Key 输入留空会保留原值；页面只返回已配置状态，不返回 Key 原文。普通用户和授权组管理员不能修改全局接口凭据。配置导出及跨环境迁移不携带此 Key，正式环境需单独配置自己的 Key；目标环境已有 Key 会保留。也可通过 api 环境变量 `JUHE_EXP_KEY` 配置，后台保存值优先。

原有阿里云、快递100配置保持可选；新配置默认使用聚合数据。

## 查询行为

- 云函数通过 HTTPS POST 请求 `https://v.juhe.cn/exp/index`，使用 `application/x-www-form-urlencoded`，提交 `key`、`com`、`no`、`dtype=json`。Key 不进入前端请求或物流轨迹缓存。
- 快递公司编码通过 `https://v.juhe.cn/exp/com` 的实时目录匹配，兼容聚合数据与其他服务商编号不同的情况；云函数实例内缓存公司目录24小时。
- 从订单 `shippingAddress.contactPhone` 自动提取收件电话后四位，以字符串提交 `receiverPhone`，保留前导零；不向此接口发送完整电话。未填写必要电话信息的快递无法完成查询。
- 返回轨迹按时间倒序。只将 `status_detail=SIGNED` 视为已签收；`status=1` 仅代表终态，不能据此把退回、拒签等标记为签收。
- 成功轨迹按订单缓存30分钟，明确签收的有效记录可继续复用。旧模拟缓存、不同服务商或不同发货批次的缓存不会替代真实查询。缓存绑定原始快递公司、运单号和发货时间；缺少这些绑定信息的旧缓存会重新查询。
- 未配置、未查到、查询错误或超时时，展示暂无轨迹或重试提示，不生成模拟轨迹。旧模拟签收缓存不再用于自动收货；原有发货超时自动收货规则仍保留。
- 重新发货会原子清除旧物流缓存、收货时间和自动收货标记。查询结果写入缓存前会复查发货批次，避免旧请求覆盖新发货缓存；即使补发沿用同一单号，也按发货时间区分。定时收货仅接受与当前发货批次匹配的真实签收证据；原有超时规则继续生效。
- 客户和管理员查询触发自动收货前，在事务中复查订单状态、运单和售后状态；正在售后的订单不会因为物流签收被自动完成。

## 查询频率限制

用户端与管理员端共用同一账号的滚动限频：任意连续5分钟最多查询3次。每次有运单且通过访问权限检查的查询都会计数，包括缓存命中和查询失败；未发货及无权访问的订单不消耗次数。换订单、切换角色、重启页面或同时发起请求不能重置额度。

服务端在 `rate_limits` 中按账号保存最近的查询时间，使用事务处理并发。超限返回 `LOGISTICS_RATE_LIMITED`，提示距离最早一次查询到期还需等待多少秒。管理员原有错误提示和用户端物流错误提示都会展示该原因。限频存储异常时停止查询，避免故障放开接口。

## 验证范围

自动化测试使用模拟 HTTP 响应，覆盖手机号后四位、承运商编码、状态解释、缓存、错误响应、密钥权限及迁移。未使用真实 Key 发起计费查询。上线前使用已开通权限的 Key 和一笔真实运单验证额度、公司匹配及接口权限。

接口依据：[聚合数据官方文档](https://www.juhe.cn/docs/api/id/43)。
