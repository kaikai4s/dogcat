# 订阅通知检查与授权流程

本次按业务发送、授权时机、后台配置、两端一键订阅四条链路检查。

客户付款时补充申请完成、远程开门和退款三个模板，和创建订单时的接单、出发、开始三个模板互补。拒绝或无法订阅不会阻止业务操作。远程开门未授权只做一次可选提示，按模板 ID 映射判断，兼容多个业务共用一个模板 ID。

进入订阅相关页面时预先刷新系统配置，授权只在点击回调中发起，不能先等待风险校验、定位或创建订单的网络请求。缺少缓存时不会等网络返回再弹微信窗口，用户可进入订阅中心加载后再次点击。授权日志异步保存，不拖住支付、接单或服务操作；多个入口同时点击共用防重复弹窗控制。

两端消息页可进入各自订阅中心，首页不展示订阅提示。客户可订阅 9 类已接入通知，宠托师可订阅 5 类；实际数量取决于后台开关及已配置 ID。每次最多 3 个不同模板，正常全部同意时分别按 3＋3＋3 和 3＋2 完成，剩余项目必须再次点击「继续订阅」。从原生授权窗口返回不会丢失剩余批次；返回页面发现后台更换模板后会刷新 ID 并清空旧批次。一次同意不代表永久授权或仍有发送次数。

订阅授权结果按云环境、登录账号和完整模板 ID 保存在当前设备，订阅中心和业务入口共用记录。页面重新创建或小程序重启后恢复展示；微信设置未返回某个模板时保留已有记录，明确返回拒绝或关闭时更新状态，总开关关闭时不显示为已授权。更换模板不会继承旧 ID 的授权。页面显示「已授权订阅」代表曾同意订阅，不表示剩余发送次数；清除本地数据或更换设备后无法从该缓存恢复。结果在微信授权返回后保存，不等待云端授权日志，存储异常不阻塞业务。回归覆盖页面重建、重启、设置变更、账号和环境隔离、其他入口授权及延迟响应。

后台已有的「纠纷更新模板」仅为历史预留，没有业务发送点。本次明确标注为预留，两端显示暂未开放，不计入一键授权，也不清除已有配置。用户仍可在售后详情中查看处理进度，退款结果使用独立通知正常发送。

指定预约支付不再提前通知客户「接单成功」。历史提前入队的接单通知保留为 skipped。延迟的前往服务提醒发现订单已出发、开始、完成、取消或改派时跳过发送，保留记录。

## 验证范围

回归覆盖模板字段、实际业务触发、接收人、重复触发、队列重试、旧消息跳过、后台保存与公共配置、一键订阅分批、配置更新、同步点击授权及拒绝后业务继续。云函数配置已声明 `subscribeMessage.send` 权限及每 5 分钟的定时任务。

本地测试模拟微信接口，不等同于云环境已配置或真机送达。发布时仍需部署 api、更新小程序、核对模板 ID 与字段，接单成功模板还需要平台客服电话；由客户和宠托师分别授权后，用测试订单核验微信收信及后台投递记录。

## 首页与授权失败补充修复

两端首页已移除订阅提醒视图、专用样式引用及权限状态刷新；进入、返回和下拉刷新首页均不因订阅提醒读取微信权限或弹窗。消息页仍保留订阅管理入口，业务操作中的授权时机继续保留。

订阅中心使用「批量订阅」按钮，每次点击自动组合最多 3 个模板，不能承诺一次即可全部授权。继续卡片显示本轮范围、已同意数、未完成数、通知名称及下一批申请数量。只有明确返回 accept 的模板才移出待完成列表；reject、ban 和缺失结果仍参与后续批量组合，不触发全局逐项模式。微信返回 filter 后记录该次过滤组合，下次避开该组合并搭配其他模板。模板配置或类型错误仅隔离出错的批次，先批量处理其他通知，再单独检查出错项；单项 20001 才判定为不可用，其他错误保留待重试。普通网络错误保留原批次重试。本轮已成功项不重复申请，只有所有模板均返回 accept 才显示全部完成。拒绝被微信记住时提示先调整微信通知设置，不自动反复弹窗。延迟的权限查询不得覆盖刚刚授权的结果。

回归覆盖两端正常批量、部分结果继续组批、过滤组合拆分、局部模板错误、共享模板去重以及首页无订阅提示。页面另使用微信开发者工具附带的 WXML/WXSS 编译器检查；本地模拟和独立编译均不等同于真机授权验证。

后台增加完整模板 ID 的说明，模板编号与其他小程序的模板 ID 不可替代。未弹窗的真机具体原因仍须结合前台返回的微信错误码与当前后台配置确认，本地模拟无法证明真机授权或送达。

用户确认尚未配置模板 ID 后，补充了空值、纯数字模板编号、明显占位值和非法字符的校验，订阅中心及点击授权共用规则。后台禁止保存明显错误的非空 ID，允许留空等待配置；这些本地检查不能证明模板属于当前小程序。微信对单项返回 20001 后，该 ID 在本页面内不可再参加批量申请，切换「全部 / 常用」或打开微信设置也不会重新加入。全部不可用时显示「待平台配置」，不再引导继续订阅；管理员配置后可点「重新检查配置」刷新并重新尝试。默认配置仍为空，不自动填入示例或用户在聊天中提供的 ID，也未修改云端现有配置。

首页轮播配置独立于订单、宠托师、优惠券等聚合数据加载。按云环境缓存有效图片地址 10 分钟，重新进入首页优先渲染缓存，刷新不清空现有图片；冷启动显示等高加载占位，避免先展示静态宣传背景再突然替换。缓存保留跳转地址，后台禁用或更换素材及时生效，离开页面的旧响应不会覆盖新状态。图片加载错误允许一次地址更新重试，公网图片地址直接使用。下拉刷新同步更新首页与轮播。

## 2026-10-23 补充：固定分组及管理员通知

用户、宠托师订阅中心增加固定分组按钮，按不同模板 ID 每三个一组，末组保留余项。同一模板的多个业务别名放在同组，同意一次只增加一次该模板机会。完成后再点本组可重新申请整组；部分拒绝或过滤时，继续按钮仅重试未同意项。仍通过原有授权记录与余额接口计数，不在前端直接增加余额。

后台接单模板配置中的“伴宠师”改为“宠托师”。这是小程序中的展示文案；微信原生通知的模板标题与字段名称由微信公众平台所选模板决定，改前端文案不会修改微信模板本身。

管理员已有站内通知链路 `notifyAdmins → admin_notifications → 系统通知/首页未读`。超时未开始、超时未完成、订单转加急、SOS、入驻申请等已有业务触发点。庄园定制入口新增待处理及制作中的申请数量，草稿、已完成、驳回、取消不计数；这是业务待办数量，进入列表查看不会清零，处理完毕后返回首页刷新。

管理员微信订阅目前没有独立授权入口，也没有按管理员身份/权限挑选收件人并发送的链路。当前后台已配置模板均服务于客户或宠托师，不能仅凭填写 ID 就认为管理员会收到。代码中的现有模板候选如下：

- `serviceProgress`：字段包括服务项目、状态、备注、订单号、宠托师，语义上适合订单超时提醒；能否用于管理员运营提醒仍需在当前小程序微信公众平台核对模板适用场景。
- `orderChat`：发送人、内容、时间，适用于会话未读，不宜改造成审核待办。
- `withdrawResult`：表示提现结果，不能替代提现待审核通知；员工认证、培训视频、实习转正、宠物疫苗、庄园定制等待办也没有现成的专用审核提醒模板。
- 支付、出发、开门、退款、服务前提醒等模板目前面向具体服务参与者，不建议作为管理员通用告警。

若后续接入管理员微信通知，应先选定并核对超时订单/待审核模板及字段，再补管理员主动订阅、按实际权限与有效管理员身份筛选接收人、业务触发、幂等发送和失败重试；通知跳转应指向管理员有权访问的后台页面。本次未虚构模板 ID，未调整云端设置，也未声称管理员微信推送已接通。

用户首页及“我的”页的宠托师入口单独读取 `staffMessage.getUnreadSummary` 的订单与系统未读合计，不混入用户端消息数；前台每30秒刷新，隐藏/销毁页面后停止。
