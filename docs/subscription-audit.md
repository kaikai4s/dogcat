# 订阅通知检查与授权流程

本次按业务发送、授权时机、后台配置、两端一键订阅四条链路检查。

## 已接入的模板

| 通知 | 接收人 | 发送时机 | 合适的授权入口 |
| --- | --- | --- | --- |
| 接单成功 44245 | 客户 | 宠托师接单、指定单自动接单 | 创建服务订单、客户订阅中心 |
| 宠托师出发 77732 | 客户 | 每场服务点击出发 | 创建订单、订单详情补充授权 |

客户付款时补充申请完成、远程开门和退款三个模板，和创建订单时的接单、出发、开始三个模板互补。拒绝或无法订阅不会阻止业务操作。远程开门未授权只做一次可选提示，按模板 ID 映射判断，兼容多个业务共用一个模板 ID。

进入订阅相关页面时预先刷新系统配置，授权只在点击回调中发起，不能先等待风险校验、定位或创建订单的网络请求。缺少缓存时不会等网络返回再弹微信窗口，用户可进入订阅中心加载后再次点击。授权日志异步保存，不拖住支付、接单或服务操作；多个入口同时点击共用防重复弹窗控制。

两端首页和消息页均能进入各自订阅中心。客户可订阅 9 类已接入通知，宠托师可订阅 5 类；实际数量取决于后台开关及已配置 ID。每次最多 3 个不同模板，剩余项目必须再次点击「继续订阅」。从原生授权窗口返回不会丢失剩余批次；返回页面发现后台更换模板后会刷新 ID 并清空旧批次。一次同意不代表永久授权或仍有发送次数。

后台已有的「纠纷更新模板」仅为历史预留，没有业务发送点。本次明确标注为预留，两端显示暂未开放，不计入一键授权，也不清除已有配置。用户仍可在售后详情中查看处理进度，退款结果使用独立通知正常发送。

指定预约支付不再提前通知客户「接单成功」。历史提前入队的接单通知保留为 skipped。延迟的前往服务提醒发现订单已出发、开始、完成、取消或改派时跳过发送，保留记录。

## 验证范围

回归覆盖模板字段、实际业务触发、接收人、重复触发、队列重试、旧消息跳过、后台保存与公共配置、一键订阅分批、配置更新、同步点击授权及拒绝后业务继续。云函数配置已声明 `subscribeMessage.send` 权限及每 5 分钟的定时任务。

本地测试模拟微信接口，不等同于云环境已配置或真机送达。发布时仍需部署 api、更新小程序、核对模板 ID 与字段，接单成功模板还需要平台客服电话；由客户和宠托师分别授权后，用测试订单核验微信收信及后台投递记录。

## 首页与授权失败补充修复

两端首页首屏直接使用页面原生 view 渲染订阅提醒，共用状态计算逻辑，显示平台是否开启、是否配置模板、微信总开关及可订阅数量。返回首页重新读取状态；入口始终保留，不在页面刷新时主动弹微信授权窗口。两端首页与订阅中心共用通知目录，预留的纠纷模板仍不计入授权。

开发者工具曾报告 `components/subscription-reminder/index` 未找到。组件源码和路径虽齐全，原先的单元测试不能覆盖开发者工具按需加载时的注册过程；现已删除该自定义组件及两端页面注册，提醒直接随页面渲染，避免该加载失败影响首页入口。状态刷新回归改为执行两端真实页面生命周期，离开页面后丢弃迟到的配置及权限响应。

本次修复通过 217 项小程序回归，以及微信开发者工具附带的 WXML/WXSS 编译器检查。开发者工具服务端口关闭，无法自动清理其编译缓存或核验当前模拟器控制台；本地独立编译通过不等同于真机授权验证。

订阅中心使用「分批订阅」按钮，每次点击最多申请 3 个模板，不能承诺点击一次即可全部授权。独立的继续卡片显示本轮范围、已同意数、未完成数和待完成通知名称。微信在弹窗前拒绝调用时保留错误码和待申请批次；模板配置或类型错误允许下一次点击改为逐项申请，单个不可用模板不会一直阻塞其他通知。普通网络错误保留原批次重试。只有明确返回 accept 的模板才移出本轮待完成列表；reject、ban、filter 和缺失结果均保留。优先分批申请尚未请求的模板，然后由用户再次点击逐项申请未完成项，避免相似模板重复被过滤，已成功项在本轮内不重复申请。拒绝被微信记住时提示先调整微信通知设置，不自动反复弹窗。只有本轮所有模板返回 accept 才显示全部订阅完成。微信记住选择后可能直接返回结果而不弹窗口，这种情况以返回值为准。延迟的权限查询不得覆盖刚刚授权的结果。

后台增加完整模板 ID 的说明，模板编号与其他小程序的模板 ID 不可替代。未弹窗的真机具体原因仍须结合前台返回的微信错误码与当前后台配置确认，本地模拟无法证明真机授权或送达。

用户确认尚未配置模板 ID 后，补充了空值、纯数字模板编号、明显占位值和非法字符的校验，两端首页、订阅中心及点击授权共用规则。后台禁止保存明显错误的非空 ID，允许留空等待配置；这些本地检查不能证明模板属于当前小程序。微信对单项返回 20001 后，该 ID 在本页面内不可再参加批量申请，切换「全部 / 常用」或打开微信设置也不会重新加入。全部不可用时显示「待平台配置」，不再引导继续订阅；管理员配置后可点「重新检查配置」刷新并重新尝试。默认配置仍为空，不自动填入示例或用户在聊天中提供的 ID，也未修改云端现有配置。

首页轮播配置独立于订单、宠托师、优惠券等聚合数据加载。按云环境缓存有效图片地址 10 分钟，重新进入首页优先渲染缓存，刷新不清空现有图片；冷启动显示等高加载占位，避免先展示静态宣传背景再突然替换。缓存保留跳转地址，后台禁用或更换素材及时生效，离开页面的旧响应不会覆盖新状态。图片加载错误允许一次地址更新重试，公网图片地址直接使用。下拉刷新同步更新首页与轮播。
