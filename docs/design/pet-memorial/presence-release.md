# 同园访客同步（目标 50–100 人）

## 已实现的范围

每个独立纪念园同步访客的行走、停止、朝向、男生/女生形象，以及查看地图、挑选位置、查看小筑卡片的简单状态。本人移动直接响应摇杆；访客不互相碰撞。打开独立回忆页面、隐藏/离开园区会离场，返回重新加入。同一账号同时使用两个设备时，后进入的会话生效，旧会话显示提示并停止，避免互相争抢位置。

小筑申请占位及管理员审核在原业务事务中同步递增公开园区版本，在线客户端收到推送后合并刷新地图，失败会重试。回忆文字、图片、视频、音乐仍走已有权限和审核接口，不进入访客同步数据。

后台“纪念园管理”支持创建、命名多个独立园区，当前共用 `garden-ortho-v2` 场景素材。新园区 ID 使用 `garden_<hash>`，所有占位、审核刷新、同步房间和本地位置都按园区 ID 隔离。原有未记录 gardenId 的数据只属于默认时光纪念园。同一账号切园区会在事务中移除旧房间人物；新加入校验园区存在。暂停接收新申请不影响探望已有小筑。

## 发布步骤

1. 部署 `api` 云函数，运行已有管理员权限保护的 `initData.setupDatabase`（首次初始化需密钥），核对返回的索引结果，或在云控制台单独创建 `pet_memorial_live` 集合和非唯一复合索引 `idx_memorial_live_scene`（`kind` 升序、`sceneId` 升序）。不需要删除/重建现有数据。
2. 对这个新集合设置 `cloudfunctions/api/database-rules/pet_memorial_live.json` 的自定义安全规则：仅登录用户可读 `kind == 'scene'`，客户端所有写入均禁止。私有 `kind == 'session'` 必须禁止客户端读取，即使是本人。**部署云函数不会自动应用数据库权限。**
3. 发布小程序。沿用现有云环境选择 `getCloudEnv()`，监听环境必须与 API 环境一致。不需要重新上传人物图片或配置新的图片模型密钥。
4. 在真实微信中用两个不同账号验收，并在目标云环境完成 50/100 人并发验收。这里只完成了本地代码和模拟验证，未部署、未执行真实云端负载测试。

先确认环境与当前小程序版本一致，来自 `miniprogram/envList.js`：

- 开发版 / 体验版：`cloud1-5gnhqn4t0554c1d9`
- 正式版：`production-d2g5jx277f41a81a6`

进入微信开发者工具的“云开发”或对应云开发控制台，选择上述环境，打开数据库。若没有 `pet_memorial_live`，先创建空集合；无需手工写入场景数据。

打开集合的“索引管理 / 索引”，选择“添加索引”，按下表依次添加字段，方向均选升序，唯一性均选“非唯一”。已有同字段顺序的索引就复用，不重复创建。

| 集合 | 索引名 | 字段顺序（全部升序） | 用途 |
| --- | --- | --- | --- |
| pet_memorial_live | idx_memorial_live_scene | kind → sceneId | 同园实时监听，优先创建 |
| platform_configs | idx_memorial_catalog | key → _id | 纪念园列表 |
| platform_configs | idx_memorial_garden_plots | key → gardenId → _id | 按园区读取占位与已安放小筑 |
| platform_configs | idx_memorial_owner | key → ownerOpenid → _id | 我的时光小筑 |
| platform_configs | idx_map_application_pending | key → status → _id | 小筑、回忆、画像审核队列，复用已有索引 |

保存后等状态为可用 / 创建完成，再重新进入园区。开发环境和正式环境的数据与索引互不共享；先完成正在测试的环境，上线前再配置正式环境。

`pet_memorial_live` 的“权限设置”选择自定义规则，内容为：

```json
{
  "read": "auth != null && doc.kind == 'scene'",
  "write": false
}
```

不能设成所有用户可读，否则会暴露 `kind: session` 的私人同步凭据。业务写入由云函数完成。`platform_configs` 仍只通过云函数访问，无需开放客户端权限。

上传部署 `api` 云函数和重新编译 / 上传小程序是独立步骤，不会替代索引与权限配置。在“园区设置”看连接详情；配置好后点“重新连接同园访客”。若仍出错，记录那里显示的阶段、错误码和原始错误，继续区分索引、权限、环境或网络问题。

## 位置恢复

同一设备按云环境、账号、独立园区 ID 和地图版本保存坐标；移动时每 3 秒检查点保存，退出 / 切后台立即保存。再次进入从上次位置继续；已被景物或小筑占用的旧位置会调整到附近安全点。未登录、损坏或越界的缓存回入口。不提供跨设备位置同步，清除微信缓存也会清除本地位置。

## 同步参数与开销

- 一条云数据库实时监听连接/客户端，监听同园区最多 65 个文档（64 个散列人物分片 + 1 个园区版本文档）。仅处理改变的分片，不在每次动作时读取整个园区。
- 行走最多每 250 ms 上报一次；静止每 4 秒一次心跳；每个连接只保留一个未完成的动作请求。慢网时下一次读取最新位置，丢弃中间过时状态，不累积发送队列。
- 远端为每个访客维护连续的播放时钟，按最近消息间隔和抖动调整目标缓冲（300–1500 ms）。在已确认的坐标之间逐帧插值、缓慢调整播放速度，短暂缺包时渐缓靠近最后坐标；消息到达不会直接跳动人物位置。步行动画按实际播放距离推进，转弯按正在播放的路段朝向。跨大距离回到入口、切换会话时直接校准；不预测越过最后确认的位置。
- 动作携带可选的 `sampledAt`（本次采样的客户端毫秒时间）；仅用同一访客相邻采样的时间差，消除云函数耗时变化造成的动作快慢变化。它不用于鉴权、TTL、节流或日期显示，设备时间有偏差也不影响其他人；旧版本没有该字段时回退到服务端写入时间，时间跳变时用接收间隔恢复。采样时间不参与状态变化判定，静止时仍只发心跳。
- 暂时网络断线会指数退避重试；只有已被服务端确认的人物状态连续 30 秒未从订阅返回，才会重建监听。缺索引、权限或集合等配置错误停止自动重试，在园区设置展示详细错误，配置后点击“重新连接同园访客”；离开会主动清理，异常退出的访客约 20 秒无心跳后从画面消失。重新进入前的请求由会话、进入序号和动作序号拦截。
- 会话有效期一小时，续期重新验证账号状态。快速动作依靠可信 OPENID + 服务端私有会话和事务节流校验，不反复执行每分钟 60 次的普通业务限流。坐标仅用于显示；不能用这些客户端坐标决定业务权限或奖励。
- 人物只共享两套已缓存的精灵图，视野外不绘制；帧循环不调用 `setData`。访客人数和连接提示仅在变化时更新。
- **100 人持续移动的上限约为 400 次动作云函数/秒**，每次正常提交读取两个文档、写入两个文档，并向同园监听者推送变更。64 分片减小同文档写入竞争，不能消除推送扇出、数据库成本和平台配额限制。需要监测云函数并发/耗时、事务冲突、数据库读写、实时连接和消息额度；若云端容量不满足，下一步应使用有部署资源的 WebSocket 房间服务合批广播，而不能无限提高上报频率。
- 250 ms 是上报目标间隔，不是端到端延迟承诺。网络、云函数冷启动、数据库推送和自适应缓冲都会增加对方所见的延迟。慢网下用更长缓冲换取连续移动，不能消除传输延迟；严重断线仍会停在最后确认的位置。

## 远端人物卡顿修复（2026-11-12）

问题可复现：旧版固定回看 300 ms，但串行云请求耗时可能超过 250 ms。两次消息之间，旧缓冲耗尽就切待机；下一包到达又直接跳到较新位置，所以会反复“停一下、跳一步”。现改为上面的连续播放时钟，并避免将“渲染暂时落后超过 240 像素”误判为传送。

发布这次修复：先上传部署 `api` 云函数（保留 `sampledAt`），再重新编译 / 上传小程序，让两个测试账号均使用更新版本。不需要新增索引、修改数据库权限或重新上传人物素材；此处未代为部署。

验证结果：

- 同一组确定性数据，60 FPS、速度 120 世界单位/秒，预热 5 秒后观测 20 秒。每 650 ms 一包时，停顿从 31 次降到 0 次，单帧最大位移从 42 降到约 2.12 世界单位。250/450/900 ms 间隔及 250–700 ms 混合间隔同样通过；同时覆盖 30 FPS、乱序、成批推送、转弯、停走、断线、旧版本、设备改时间和 100 人插值。
- 两个独立浏览器页面，真实客户端发送循环 + 本地 BroadcastChannel，额外模拟每次云请求 650 ms 延迟。旧、新播放逻辑消费同一批消息，4.3 秒观测窗口共 258 帧：旧版停顿 7 次、新版 0 次，最大单帧位移约 44.74 → 2.11；停止后的远端坐标与发送端完全一致。此模拟不访问云数据库。预览可用 `native.html?environmentPreview=1&presenceDelay=650` 复现慢请求。
- 全量 3108 项测试通过，API 依赖兼容检查通过。100 人本地插值计算的单帧 p95 约 0.016 ms，仅代表这一计算模块，不包含画面渲染或云端开销。数据保存在 `presence-benchmark-results.json` 的 `movementSmoothing`。
- 平滑存在延迟代价：650 ms 间隔的无传输延迟模拟，修复后最大播放落后约 897 ms；真实网络还需加上传输耗时。因此仍需两个微信真机更新后验证，并按下面的真实云端验收记录延迟。它不构成 100 人真实网络或手机帧率保证。

### 边界复查补修（2026-11-12）

- 修复低帧率积累延迟：场景本地碰撞计算将时间步长限制在 50 ms，之前远端播放也误用了这个时间步长。现在远端使用实际帧间隔（单帧最多 250 ms），本地碰撞仍保留原限制。40 秒模拟中，10 FPS 下的最大播放落后由约 7.84 秒降至 0.34 秒；5/15 FPS 也没有持续累积。这不表示提高了设备帧率。
- 修复长断线后的慢速追赶：连续行走状态超过 2 秒未收到新位置后，下一条消息从当前显示位置平滑衔接到新确认位置，不把无消息的几秒钟当成一段缓慢行走。7 秒中断的测试在恢复 1 秒后，显示位置与最后确认位置的差距从约 171 降到 47 世界单位；不越过已确认位置。
- 修复发送端时钟向前跳变：相邻采样时间差与接收间隔相差 2 秒及以上时，放弃异常采样间隔，回退接收间隔。新增向前调整 10 秒的回归，不再产生长时间的慢速动作片段。
- 新增 4 项回归（包含场景调用链与独立播放模块），全量 **3112 项测试通过**；API 依赖兼容检查和本地浏览器预览通过。本次补修只修改小程序运行代码；若上一轮的 `api` 更新尚未部署，仍需按上节一起部署。未执行新的真机或真实云端并发验收。

## 本地验证（2026-11-12）

- 后端内存事务模型：100 个独立用户、每用户连续 4 次移动，身份不串、记录不丢；覆盖乱序、重复、旧会话退出、延迟加入、过期清理及业务版本回滚。该模型串行提交事务，**不模拟云数据库事务冲突/吞吐**。
- 客户端：慢请求不积压；发送节流、心跳、监听重连、迟到回调、隐藏时的未完成请求、静默断线和 100 人插值均有回归测试。
- 两个独立浏览器页面（本地 BroadcastChannel 模拟推送）：看到对方从 `(1536, 1430)` 移至约 `(1536, 1516)` 并停止，切换女生和打开地图可见，离开后立即移除。无页面脚本错误。模拟器不连接生产数据。
- 桌面浏览器 390×844、DPR 1，男女素材预热，所有人集中在视野内。每组 150 次同步 JS/Canvas 提交测量：1 人 p95 0.2 ms，50 人 p95 0.5 ms，100 人 p95 0.6 ms；同步批量测量存在 103.7–172.4 ms 最大值尖峰。另测每组 109 个 RAF 帧间隔，p95 为 16.7–16.8 ms。原单人基线 p95 0.3 ms、最大 92.3 ms。
- 初次同步实现的全量回归 3036/3036 通过（含重连诊断、位置恢复和画像流程）；API 依赖兼容检查、图标检查、`git diff --check` 通过。后续卡顿修复结果见上节。
- 原始结果见 `presence-benchmark-results.json`。这不是低端手机帧率或真实云网络延迟证明，也不能据此保证永不卡顿。

## 真机/云端验收

用开发/预发布环境和测试账号，不向真实园区注入测试访客。分别进行 50 人、100 人持续移动至少 10 分钟，记录接收延迟 p50/p95、人物停顿、客户端帧耗时/长帧、云函数 p95、错误率和事务重试。包含同位置聚集、全园分散、同时切形象、停走、飞行模式恢复、切后台、同账号换设备、审核占位、消息乱序及设备时间偏差。建议以移动延迟 p95 < 800 ms、目标手机帧率稳定且无持续请求积压作为首轮验收目标；达不到则调整服务容量/传输架构后重新测量。

多园区补充验证：2026-11-12 全量测试 3052/3052 通过。相同地块在不同园区独立占用，旧文档只归属默认园区；切园区事务移除旧房间人物，旧房间报文无法覆盖新会话。园区名称、暂停新申请与新增索引说明已同步到发布文档；未执行云端压力验收。
