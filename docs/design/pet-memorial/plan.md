# 宠物纪念园建设方案

工作分支：`feature/pet-cemetery-scene-split`。本文件是需求和实施草案，尚未实现功能。

## 已明确的需求

- 管理员可创建多个独立纪念园，为每个园区命名。
- 用户控制自己的人物在园区中行走，走近可用墓位后，为离世宠物申请创建墓碑。
- **园区内所有可用绿色草坪均铺设整齐的墓位网格，不限定少数建造区。**
- 图中树木、灌木等遮挡区域不能放置墓碑；道路、围墙等非草坪区域也不能放置。
- 提供多种墓碑样式，墓碑显示宠物名字和主人留下的话。
- 主人可以在墓碑处上传、编辑生平：文字、多张图片、多个视频。
- 主人决定生平是否公开；公开后，所有有权进入园区的用户均可查看。

## 建议采用的首版规则

以下是规划默认值，尚未由用户逐项确认，可在开发前调整。

| 项目 | 建议 |
| --- | --- |
| 园区组织 | 平台统一管理、用户自由选择园区；与居住小区独立 |
| 建碑 | 首版免费申请，管理员审核后出现正式墓碑 |
| 数量 | 一只纪念宠物对应一座有效墓碑；一名用户可以纪念多只宠物 |
| 生平可见性 | 新建时默认仅自己可见，主人主动开启公开；平台审核人员按权限处理内容 |
| 墓碑外观 | 宠物名、碑文和样式属于园区公开外观，申请页明确提示；生平隐私开关单独控制详细文字、图片和视频 |
| 宠物来源 | 可以关联自己的现有宠物，也可以新建独立纪念档案，允许纪念以前未在平台注册的宠物 |
| 日期 | 生日、离世日期允许未知，不强制编造日期；业务时间和显示统一北京时间 |
| 氛围 | 安静、温暖、克制；纪念互动可关闭，环境音默认关闭 |

关联已有宠物时，保留原资料和历史订单。纪念档案创建、现有宠物离世状态变更应分开处理并说明影响，不能直接删除原宠物或悄悄改变正在进行的订单。

## 草坪、网格和放置规则

### 全草坪网格

1. 以统一的地面坐标建立规则行列网格，每格保存固定 `row/col`，从近到远保持相同的地面间距。
2. 经过场景透视投影，屏幕上近处格子较大、远处较小，排列连续整齐；不能用随意散点放置。
3. 在园区边界内逐块标记草坪范围，覆盖可用的绿色草坪。道路、土地区域、围墙和远景树林不算草坪。
4. 在同一坐标系标记树干、树冠遮挡范围、灌木、花坛、石头等障碍，以及必要的安全留边。
5. 墓位取规则网格与合法草坪范围的交集。障碍处留下空格，后续格子仍保持原行列对齐，不为避障挤乱排列。
6. 网格间预留人物通行间距。墓碑占地不能堵住到达墓碑正面的路线；完成摆放后用户仍能走出来。

规则用一句话表示：**完整占地在草坪内 + 不碰任何障碍 + 墓位空闲 + 当前园区开放申请 + 人物已走近。**

不能只验证墓碑中心点：底座四边、装饰外伸和安全间距都应进入占地校验。不同样式保存占地轮廓；首版优先把样式统一适配单格，较大款式若确实需要多格，必须整块连续占用并原子提交。

### 放置时的显示

- 平时隐藏密集网格；靠近空位有轻提示，点“选择纪念位置”才显示附近网格。
- 可申请：细线淡绿；选中：暖金；已占用：显示已有墓碑；障碍和非草地：不显示可选墓位。
- 在编辑预览中尝试越界或覆盖障碍时，显示红色轮廓及具体原因。
- 选中远处空格可以导航至旁边；到达后才允许正式申请。
- 草坪与道路均可在允许区域内行走，墓碑底座、树木和灌木参与碰撞。
- 列表中的“前往我的纪念碑”进入所属园区并引导至墓碑，不要求用户记忆坐标。

### 管理员地图能力

管理员通过地图模板新建园区。模板包含背景、透视标定、草坪多边形、障碍、网格尺寸、出生点、边界及相机范围。

首版提供已标定模板和墓位启停、障碍调整、可用位置预览；完整自由地图编辑器可后续增加。新园区继承同一模板但拥有独立墓位和名称。发布前检查出生点与可放置格子的可达性。

已被占用的墓位编号与坐标不能因改名、调整网格或重新扫描而变化。地图版本更新先预览冲突；与已有墓碑冲突的修改应阻止发布，或通过明确迁移流程处理。

## 用户流程

`选择园区 → 人物入园 → 走近空格 → 选择宠物与墓碑 → 填写碑文 → 预览 → 提交申请 → 审核通过 → 墓碑出现 → 编辑生平`

### 申请表与预览

- 宠物名字、物种、可选照片，生日和离世日期可选。
- 选择墓碑样式，填写短碑文；字符上限作为产品配置，预览与实际渲染使用同一套截行规则。
- 展示真实背景上的位置、大小和完整文字预览；较长生平进入详情阅读。
- 碑文动态绘制，保留风格统一的刻字区域；不能把用户文字写死在素材中。
- 草稿保存到用户账户。浏览和写草稿不永久占位；提交前按需使用短期占位，并清楚显示是否已保留位置。
- 同一格多人提交时由服务端决定唯一成功者，其他人保留草稿并选择其他位置。

### 审核与占位

- 状态：草稿、待审核、已通过、已退回、已撤回。
- 短期占位与“待审核”分开：临时占位到期可释放，已提交且待审核的墓位不能因为编辑占位计时结束而被他人获得。
- 审核通过时，申请、墓位占用和正式纪念碑一起提交；重复点击或网络重试不产生第二座碑。
- 退回或撤回释放对应申请持有的墓位，保留申请内容；不误释放后来由他人取得的位置。
- 园区暂停申请时，已存在的纪念碑仍可按规则访问；存在纪念碑的园区优先归档，不直接删除。

## 墓碑、生平与纪念互动

### 样式

首批建议整理 4 类：简约拱碑、阶梯石碑、花园纪念碑、烛光纪念碑。用户提供的素材中狗雕像款作为犬类可选样式；猫及其他物种先使用中性爪印款。猫雕像等需另补素材。

各样式统一落地点、投影方向、文字安全区和占地大小。装饰不应盖住名字，墓碑被选中时显示清晰的姓名卡片，缩小时不强求读出全部碑文。

### 生平内容

- 用“回忆记录”形式添加多篇内容，每篇可含文字、多图和多个视频，也支持一篇长生平。
- 图片支持排序、说明、预览；视频支持封面、标题、上传进度、失败重试和独立删除。
- 视频只在用户主动打开后播放；退出详情停止播放，地图不预加载所有原视频。
- 上传、处理中、审核中、可展示、失败是不同状态；不能把“上传成功”直接视为“公开发布成功”。
- 首版完整交付应包含多视频能力。具体文件大小、时长、数量和处理方式在上传链路验证后形成后台可配限额，不在规划阶段假称已有能力。
- 删除文章或媒体时先解除展示引用，再按保留策略清理文件；审核和上传失败产生的孤立文件进入清理队列。
- 主人能随时改为私密。公开展示版本和编辑草稿分开，编辑待审核时继续显示上一个有效公开版本；改为私密则立即停止新的公开访问。

### 权限边界

- 地图只返回允许公开的墓碑外观投影，不能附带私密生平、图片原件或视频文件 ID。
- 生平详情、媒体访问、分享链接分别在服务端校验主人身份及当前公开设置；分享链接不绕过私密设置。
- 私密媒体使用受控存储和鉴权访问路径；上线前必须验证底层存储读取权限。只隐藏页面、返回永久公开 URL 不满足“仅自己可见”。
- 权限切换后清理前端展示缓存；短时授权链接的剩余可访问窗口需要验证和说明，不能承诺撤回已经被他人保存的副本。
- 纪念碑权限不能只按前端传入的 ownerId 判断。管理员审核、迁移、下架留操作记录。

### 建议补充

- 我的纪念碑：快速入园、定位、查看申请进度、编辑资料。
- 献一束花、点一盏灯：轻量纪念动作，防重复提交和刷屏；主人可关闭。
- 分享公开纪念页：接收者可阅读并进入园区寻找墓碑。
- 公共纪念点：为暂未建碑的用户保留表达思念的位置，与个人墓位分开。
- 纪念日提醒：后续做为用户主动订阅的功能，按北京时间计算日期。
- 留言墙、多人实时动作及更丰富装饰放到后续；首版先做好建碑、生平和隐私。

## 素材检查与场景实现

两张原图已按用户提供内容保存在 `source/`，尺寸均为 2048 × 1152，RGB，无透明通道。这些是设计来源，尚非可直接发布的场景资源；没有补充或推定素材授权信息。

| 原图 | 处理要求 |
| --- | --- |
| 墓碑合集 | 棋盘格已经烘焙在图里，需要逐个抠图、去背景、清理原碑文、修整边缘与阴影，分别导出真正透明的素材 |
| 园区背景 | 保留自然光与草坪道路；标定可走范围、所有草坪、树木灌木障碍及前景遮挡，不能只靠绿色像素阈值生成合法墓位 |

先选择少量完整且无遮挡的碑型验证效果，再处理全部款式。采用平面背景加独立角色和墓碑的 2.5D 方案。背景具有明显透视，现有庄园为固定等距投影，不能直接将背景贴进原世界坐标后宣称对齐。

需要一个纪念园场景坐标与投影适配层：逻辑网格、碰撞和放置在地面坐标计算，显示统一投影；按深度调整人物及墓碑大小。先在近、中、远草坪验证比例、脚底落点、触控和行走速度，再定整园网格尺寸。背景并非精确建模输出，如一套全局透视无法贴合，可使用经标定的连续区域映射；区域衔接必须保证网格顺序、行走和选择连续。

树木与灌木作为禁止建造区域；需要人物走到前景后方时，再拆分对应遮挡层。不能用一张背景图自动获得正确遮挡。竖屏优先延续现有小程序交互，背景跟随人物平移并支持有限缩放，避免整张宽图缩成不可操作的小地图。

`layout-concept.jpg` 仅说明全草坪规则网格和障碍跳格的设计方向，不是最终可建造坐标表；精细草坪与障碍标注在场景实施阶段完成。

## 实施顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 1. 素材与行走样板 | 独立纪念园入口、背景适配、人物行走、近中远网格样板、少量透明碑型 | 人物与背景比例协调，网格整齐，脚底落点正确；树木灌木不能穿越或放置；手机端可选中 |
| 2. 全草坪与园区后台 | 全草坪/障碍标注、全园墓位、园区创建命名、模板发布与墓位启停 | 所有合法草坪有规则网格，非草坪及障碍无可建位；园区互不串数据；已占墓位不被改图破坏 |
| 3. 建碑闭环 | 选位、宠物档案、样式/碑文预览、申请、审核、正式落碑 | 双人抢同格只成功一人，退回撤回释放正确，重试不重复建碑，审核通过后的外观正确 |
| 4. 首版完整内容 | 文字、多图、多视频、公开/私密、我的纪念碑、导航 | 私密内容及媒体无法越权获取；视频可上传、处理、重试和播放；跨页面返回不丢位置；长文和长名字显示正常 |
| 5. 纪念氛围与完善 | 献花点灯、分享、公共纪念点、可选音效及性能优化 | 交互不刷屏，弱网可恢复，满园仍可行走，切园无监听泄漏，低端手机实测可用 |

第一阶段用于验证技术与画面，不作为全部需求完成。首版完整交付必须包含用户要求的管理员建园、全草坪整齐网格、障碍禁放、人物行走、多样式碑文、文字多图多视频和生平隐私。

关键回归还包括：墓碑四角跨草坪边缘、装饰碰灌木、多格款式冲突、墓碑间距、无路可达、占位到期与审核同时发生、重复审核、退出时上传未完成、隐私变更与缓存、跨北京时间零点的时间记录，以及原庄园/订单功能保持正常。
