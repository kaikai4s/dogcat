# 献花与零食

每位登录访客每天可给每个已安放的小筑献花一次、放零食一次，两个动作独立计次。北京时间零点刷新，累计数量永久保留。用户也可探望自己的小筑；暂停接收新申请的园区仍可探望。

使用服务端日期与事务记录每日领取状态和累计数量；同日重复请求返回既有结果。跨午夜的旧请求要求刷新日期，不自动计入新一天。

## 场景与素材

沿用现有金白色男、女访客，金发、发光无五官面部、披风和飘带。人物到达小筑前，俯身伸手、放下心意、收手起身。男女各有独立绘制的献花与放零食动作。

鲜花使用奶白雏菊与淡桃色小花、鼠尾草绿叶、柔金丝带；零食为奶油色浅碟，盛骨头与小鱼造型的宠物饼干。两者固定放在小筑前方左右两侧，中央保留宠物画像。累计数量在小筑卡片展示；未到期的心意逐件增加，在左右两侧各按三列四排摆放。每种超过 12 件时保留花丛／零食盘的密集排列，并标出准确的当前数量，避免超出小筑占地。

后台「纪念园审核 → 鲜花与零食 · 场景显示」分别设置鲜花和零食的显示分钟数，默认 1440 分钟，支持 1～10080 分钟。设置对新献上的心意生效，到期按分钟移除，累计数量永久保留。供品按到期分钟聚合存储，最多延后 59 秒移除。设置有独立权限、管理员审计和版本冲突检查。

运行素材为透明 PNG，人物单帧 128×128、4 列×2 行、8 帧，脚底锚点 (64,115)，适配现有 Canvas2D 场景。动作朝上靠近墓碑，使用独立背面视角。素材模型生成后统一切片、去底、定位并检查透明边缘，保留提示词、原始图与预览。

## 资源交付与上线

运行资源在 `miniprogram/packageMemorial/assets/offerings-v1/`，共 6 张透明 PNG。原图在 `output/imagegen/memorial-offerings-v1/raw/`；对应提示词、来源摘要和成品 SHA256 在本目录。运行 `python3 scripts/assets/package-memorial-offerings.py` 可从原图重新整理成品。

上传包在 `output/imagegen/memorial-offerings-v1/upload/`，仅含这次新增的 6 张 PNG。开发云存储目标前缀为 `memorial-cloud-v1/packageMemorial/v1/offerings-v1/`，正式云存储同样为 `memorial-cloud-v1/packageMemorial/v1/offerings-v1/`。保留文件名和目录。小程序排除了本地大图，上传资源并发布 api 云函数后，再发布小程序。本次只生成本地上传包。

## 运行流程

打开任何已安放小筑显示永久累计和当日状态；人物沿可通行路线走到小筑前，记录心意后播放八帧弯身、伸手、收手、起身动作。前往途中可取消，未到场不计次数。隐藏或退出页面会停止路线和动作；服务端成功但响应丢失时，同一天重复操作返回已记录结果。
