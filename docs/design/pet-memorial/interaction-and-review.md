# 纪念园交互、性能与建碑审核

本轮实现已写入小程序与 api 云函数。未部署到云端、未执行微信开发者工具编译，也未在真实手机验证；浏览器验证共享场景引擎与对应布局，申请审核以本地云函数测试验证。

## 用户操作

- 竖屏顶部只保留标题和设置，性别、音乐与音效收进设置面板。音乐与音效首次默认开启，后续读取本机 memorial-sound-v1；自动播放失败不覆盖用户保存的选择。提供重试声音，并在首次交互时尝试恢复播放。
- 修复 native audio 初次设置 src 后立即 seek(0) 的调用；只在 canplay 后重播时 seek。手机音频格式、下载路径与系统打断仍需真机联调。
- 双指缩放与加减按钮可缩小到完整园区。大地图显示实际地形、地标、纪念碑及蓝色“我在这里”。点选位置后追踪，显示避开建筑和纪念碑的路线与箭头；走近路线终点提示到达。被建筑占据的点导航到附近可通行位置。
- 申请建碑：点击“申请建碑”进入大地图，选择绿色空墓位，填写宠物名字、纪念日期与寄语。提交后保留墓位；同一用户同名宠物不能重复申请待审或已建立的纪念碑。设置中的“我的建碑申请”可刷新状态、查看原因、追踪已建立的纪念碑。
- 管理员在“宠物庄园与纪念园 → 纪念碑申请审核”查看待审、已建立、已驳回记录。通过后在园区生成统一 60×62 世界单位的纪念碑；驳回须填写原因，释放墓位并允许修改后重新申请。
- 后台首页显示待审核提示，通知中心保留申请通知，审核后标记已处理；申请人收到站内审核结果。微信订阅提醒沿用 adminPendingAudit，送达取决于已有订阅授权与发送配置。

## 性能

- 静态草地、砖缝、道路缓存为 384×384 离屏瓦片，最多保留 24 张；全园视图使用单张 1536×1152 静态底图缓存。
- 拖动、缩放和区域下载完成时合并到同一动画帧重绘；摇杆 setData 最多每 50 毫秒刷新一次。
- 全园显示使用小型元数据索引，低缩放下仍只下载人物附近区域，不因缩小地图拉取全部 48 个分区。
- 路线搜索使用空间分桶和最小堆，避免偏离路线重新规划时遍历所有景物。
- 浏览器 844×390 预览实际摇杆行走：人物从 (1536,1430) 移动到 (1685.4,1318.2)，采样绘制平均 0.33ms、峰值 3.60ms。此数值仅为桌面浏览器绘制时间，不是手机 FPS 或性能承诺。

## 部署

1. 在微信开发者工具对 cloudfunctions/api 执行“上传并部署：云端安装依赖”。连同 handlers/memorial.js、config/memorial-world.json、权限配置和通知服务一起上传整个 api。
2. 清除编译缓存，重新编译小程序。沿用已上传的 world-v2、boy、girl、audio，不新增云存储素材。
3. 若启用了后台权限组，为审核人员授予“纪念园审核”的查看与审核权限。超级管理员直接可用。
4. 数据使用现有 platform_configs、admin_notifications、system_notifications 及既有订阅队列；客户端通过 api 访问。platform_configs 查询涉及 key + _id、key + status + _id、key + ownerOpenid + _id（均升序），如环境要求复合索引，在控制台创建对应索引后再验收。
5. 真机验收：首次声音开启 → 手动关闭 → 重新进入保持关闭；连续拖动、跨分区行走；横竖屏切换；申请 → 管理员收到待办 → 通过后在园区显示；驳回 → 用户收到原因且墓位释放。

## 验证

相关场景、云资源、设置、导航、性能缓存、申请事务、权限及后台提醒共 78 项测试通过；后续小修改重复运行受影响测试通过。API 依赖兼容检查通过，WXML 标签结构检查通过。并发抢位、重复提交、重复审核、非法墓位、过期地图版本、未来日期与只读管理员越权均有回归测试。
