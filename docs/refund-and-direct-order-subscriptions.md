# 退款与指定单订阅通知

在管理员后台「系统设置 → 订阅消息」开启订阅，分别填写模板 ID，不在代码中写死。

| 后台配置 | 微信模板 | 字段 |
| --- | --- | --- |
| 退款结果模板（refundResult） | 7272 | 退款金额 amount2、退款说明 thing3、退款时间 date4、退款商品 thing5、订单号 character_string6 |
| 宠托师指定单通知模板（staffDirectOrder） | 8560 新订单通知 | 订单号 character_string2、备注 thing5、服务名称 thing9、服务时间 time10、订单总价 amount3 |

退款通知发给下单客户，支持服务订单和商城订单、全额及多笔部分退款。使用本次退款金额；成功时间优先使用微信返回的实际成功时间，以北京时间展示。微信确认 SUCCESS 后提示退款成功并提醒查看原支付账户，不承诺已到账；CLOSED/ABNORMAL 展示对应失败说明。处理中、网络结果不确定及 mock 退款不发送结果通知，待现有定时退款核对确认结果。每笔退款结果分别入队，重复请求或核对不重复发送。

指定预约在支付成功后通知 requestedStaffOpenid，进入宠托师订单详情页确认。管理员派单、系统自动安排及改派后通知新的 staffOpenid，进入履约页查看；宠托师自主接单不额外消耗指定单授权。订单总价使用客户实付金额，不代表宠托师收入。每次指派有独立版本，重复投递不重复发送，再次指派可再次提醒。延迟发送前会检查状态和归属，已取消、已开始服务、已完成或指定关系过期的消息跳过并保留记录。

客户在订阅中心可单独同意退款通知，取消有可退金额的服务订单及商城售后申请时也会请求授权。拒绝或授权失败不阻止申请。宠托师在消息页进入订阅中心授权，也可在接单时补充授权；两端首页不展示订阅提示。一次性订阅次数用完后需要再次同意；每次自动组合最多三个模板，其余由用户再次点击继续订阅。

通知随业务事务入队，提交成功后尝试发送，网络失败由现有订阅队列重试。后台可查看未配置模板、未授权（43101）、过期指定关系等原因，并在补齐配置和授权后手动重试。重试保留原金额、时间和接收人。旧退款队列缺少本次金额及真实结果时间，保留历史并跳过发送，不猜测退款数据。

发布时部署 api 云函数、保持现有定时任务运行并更新小程序，在后台配置两项模板后让客户和宠托师分别重新订阅。
