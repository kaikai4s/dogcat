# 小区地图首版实施说明

日期：2026-10-23；地图交互续补：2026-10-24。此次续补代码在当前工作区，未部署到线上。

## 已实现的入口

- 用户：宠托师列表顶部「地图找宠托师」；首页优选宠托师区域也有地图链接。
- 宠托师：工作台「附近可接订单」下方独立一行的「小区地图」。按进入地图前正在使用的端固定内容：用户端仅找宠托师，宠托师端仅找订单；双角色账号也不在地图内切换。
- 宠托师公开设置：个人中心接单配置资料中的「公开服务小区」。
- 管理员：后台 → 平台配置 → 小区地图管理。分配权限时可授予 `communityMap.listAdmin`、`communityMap.saveAdmin`。

## 首次启用

1. 部署更新后的 `api` 云函数及小程序代码。通过已有初始化接口 `initData.setupDatabase` 补齐索引，或手动按 `handlers/initData.js` 中 `idx_map_*` 定义配置索引；该操作仍受现有管理员权限保护。
2. 后台进入「小区地图管理 → 待处理小区」，系统按未匹配的待接订单、已审核宠托师固定地址整理清单，显示对应数量及原因。点「选公共点并启用」，在微信地图选择公共入口/中心，自动带入可识别的名称、城市和行政区，核对后确认保存。全新小区也可直接新增，无需逐门配置别名。不能选择家庭门牌或用用户定位代替公共点。
3. 维护一次后，订单根据规范名称/别名、城市和距离自动匹配。识别东/南/西/北门及明确楼栋后缀，一期/二期、南区/北区不混为同一小区。重名且位置有歧义时继续保留在列表。历史订单读取时按同一规则匹配，不批量改写详细地址。
4. 宠托师在「公开服务小区」查看按本人固定服务地址推荐的附近驻点，支持搜索和分页；选中后确认公开小区及预约范围。平台维护小区不会自动替宠托师开启公开展示。
5. 用用户和宠托师两个账号分别检查地图、详情、指定预约和抢单。

公共小区记录保存于既有、仅服务端管理的 `platform_configs` 集合，`key=service_community`，无需开放原始订单或人员集合的客户端读取权限。查询配有频率和结果预算限制，超过预算明确报错，不静默截断。

## 地图及交互

- 每个小区一个数量气泡，普通任务和已成团拼单按可选择任务计数，拼单保留整团接单。
- 远景进行屏幕网格聚合，最多约60个显示节点，保留全部底层小区身份及数量。放大仍重叠时，可通过完整小区选择列表进入。
- 公共气泡只使用管理员核验的小区点位；人员不显示私人坐标或实时行踪。
- 原生气泡选中切换、底部面板滑入、首屏前三张卡片错峰淡入、按压反馈、局部骨架、手势拖动、半屏/展开和减少动态效果选项。
- 普通/加急、日期、范围/时间任务筛选；宠托师性别与接受指定预约筛选。
- 面板内查看详情、指定具体宠托师预约、单独抢单或接整团；稳定游标分页、请求序号、稳定标记 ID、离开页面停止刷新及网络失败提示。订单地图卡片只按服务时间和编号排序，不使用私人地址距离参与顺序。
- 抢单响应不确定时查询专用结果接口，确认之前禁止再次抢单；成功可进入订单。

## 2026-10-24 续补

- 修复地图页引用未导出的定位方法。地图定位与接单前实时定位使用隐私授权及 GCJ-02 定位，不覆盖用户已选服务地址；定位被拒绝时不发送接单请求，也不误报结果待确认。
- 工作台进入地图时带入城市、日期、普通/加急、范围与时间筛选，并通过页面事件通道带入工作台参考坐标。实际 GPS 仅用于移动视野和最终接单验证，范围筛选继续使用工作台参考位置，可点地图工具回到该位置。
- 按云环境、账号、城市、模式及筛选保存地图中心和缩放，七天过期，最多12条；缓存只保存视野几何信息，不缓存人员、订单卡片。账号变化时清理内存中的面板与卡片。后续修订已移除地图内的模式切换。
- 修复首次加载中切后台后无法恢复的问题，补充身份、视野和卡片请求乱序保护。身份检查遇到网络失败时可重试，不自动把宠托师降为普通浏览模式。
- 面板定时刷新重新验证所有已加载卡片，维持已有顺序、翻页游标及滚动位置；失效内容移除，新内容提示手动更新。触摸期间延后应用卡片更新，接单确认期间暂停定时刷新。
- 风险与小区选择浮层通过隐藏原生地图保留实例和视野；返回列表优先回到已有列表页，直接打开地图时替换当前页，避免反复叠加页面。
- 接单已发出后切后台会保留待确认提示；返回后需查询结果，避免重复提交。风险预检查或定位期间离开页面则中止后续接单操作。

发布此次续补时需要同时更新 `api` 云函数和小程序代码，后台卡片刷新接口新增 `visibleList` 返回值。

## 接入时修正的业务问题

- 公开排班仅向第三方返回预约需要的时间范围，不返回订单 ID、服务摘要和内部备注；本人排班保留原信息。
- 公开人员资料补充接受指定预约状态，范围更新待确认时暂不接受新直接预约。
- 新地图人员的对外预约圆心固定为本人确认的小区公共点；列表、详情、收藏及范围接口对已迁移档案统一使用该公共范围。旧档案保留原内部范围规则，但不再返回基于私人点的精确距离；旧规则的范围判断仍是历史兼容行为，不能宣称所有历史位置侧信道已完全移除。
- 修改已公开人员的固定服务地址/半径，会关闭地图展示并要求重新确认；后台修改小区版本后，旧确认档案暂不上图，避免悄悄移动公开位置。
- 普通订单日期筛选覆盖后续服务场次；拼单始终保留完整任务包。
- 服务端拒绝缺失/无效抢单坐标，最终接单事务再次验证各成员位置和最新服务半径；详情页也补充真实定位输入。
- 指定预约创建与接单/排班修改共享宠托师版本锁，并在创建事务中重新检查全部服务时段。待支付占用期限与已有30分钟支付期限一致；已发起但未确认关闭的支付继续占档，等待现有支付巡检核实，避免晚到成功回调与新预约冲突。
- 接单已提交后通知/消息失败不会把接单改报失败；本人重复请求可确认已接单，通知沿用既有事务出队重试机制。

### 2026-10-25 再次预约小区关联续查

- 修复再次预约未带回原地图小区及新增申请、下单页又无条件清空关联的问题。公开订单再次预约时，服务端按当前启用状态、服务城市及3公里距离重新核验用户明确选择的小区；待审核申请保留编号与公共名称，已通过申请解析为当前公共小区。实际服务地址、门牌和上门坐标仍取历史订单，公共小区只返回白名单字段。
- 历史关联已停用、不存在、跨城市、超距或申请失效时，保留再次预约的其他内容，清空关联并持续提示重新选择；附近列表加载、搜索或重试不会误清除已恢复的有效选择。旧自动匹配不会被升级为3公里显式选择；指定预约不恢复隐藏的小区字段。数据库异常仍向调用方报告，不能当作历史关联失效而静默忽略。
- 再次预约的异步页面渲染回调也核对地址请求序号；用户已换地址、正在提交或页面已卸载时，不再恢复旧小区。换地址或城市仍清除旧关联，取消及重新选择会清除失效提示。下单校验同时拒绝失效申请、缺失关联目标及申请目标与所选小区冲突的组合。
