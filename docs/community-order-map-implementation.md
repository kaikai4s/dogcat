# 小区地图首版实施说明

日期：2026-10-23。代码在当前工作区，未部署、未提交到线上。

## 已实现的入口

- 用户：宠托师列表顶部「地图找宠托师」；首页优选宠托师区域也有地图链接。
- 宠托师：工作台「附近可接订单」中的「小区地图」；有宠托师角色的账号可在地图页切换找订单/找宠托师。
- 宠托师公开设置：个人中心接单配置资料中的「公开服务小区」。
- 管理员：后台 → 平台配置 → 小区地图管理。分配权限时可授予 `communityMap.listAdmin`、`communityMap.saveAdmin`。

## 首次启用

1. 部署更新后的 `api` 云函数及小程序代码。通过已有初始化接口 `initData.setupDatabase` 补齐索引，或手动按 `handlers/initData.js` 中 `idx_map_*` 定义配置索引；该操作仍受现有管理员权限保护。
2. 在后台新增小区，填写城市、行政区、规范名称及必要别名，通过地图选择公共入口/公共中心，核验后启用。不能选择某个客户或宠托师家庭位置。
3. 订单根据服务地点名称/别名、城市和距离匹配已核验小区。存在歧义或未匹配时不强行上图，原列表继续可查看，地图提示未匹配任务数。历史订单按同一规则读取，不修改其详细地址。
4. 宠托师在「公开服务小区」选择匹配的小区，确认公开驻点与对外预约范围，开启展示。历史档案不自动公开。
5. 用用户和宠托师两个账号分别检查地图、详情、指定预约和抢单。

公共小区记录保存于既有、仅服务端管理的 `platform_configs` 集合，`key=service_community`，无需开放原始订单或人员集合的客户端读取权限。查询配有频率和结果预算限制，超过预算明确报错，不静默截断。

## 地图及交互

- 每个小区一个数量气泡，普通任务和已成团拼单按可选择任务计数，拼单保留整团接单。
- 远景进行屏幕网格聚合，最多约60个显示节点，保留全部底层小区身份及数量。放大仍重叠时，可通过完整小区选择列表进入。
- 公共气泡只使用管理员核验的小区点位；人员不显示私人坐标或实时行踪。
- 原生气泡选中切换、底部面板滑入、首屏前三张卡片错峰淡入、按压反馈、模式滑块、局部骨架、手势拖动、半屏/展开和减少动态效果选项。
- 普通/加急、日期、范围/时间任务筛选；宠托师性别与接受指定预约筛选。
- 面板内查看详情、指定具体宠托师预约、单独抢单或接整团；稳定游标分页、请求序号、稳定标记 ID、离开页面停止刷新及网络失败提示。订单地图卡片只按服务时间和编号排序，不使用私人地址距离参与顺序。
- 抢单响应不确定时查询专用结果接口，确认之前禁止再次抢单；成功可进入订单。

## 接入时修正的业务问题

- 公开排班仅向第三方返回预约需要的时间范围，不返回订单 ID、服务摘要和内部备注；本人排班保留原信息。
- 公开人员资料补充接受指定预约状态，范围更新待确认时暂不接受新直接预约。
- 新地图人员的对外预约圆心固定为本人确认的小区公共点；列表、详情、收藏及范围接口对已迁移档案统一使用该公共范围。旧档案保留原内部范围规则，但不再返回基于私人点的精确距离；旧规则的范围判断仍是历史兼容行为，不能宣称所有历史位置侧信道已完全移除。
- 修改已公开人员的固定服务地址/半径，会关闭地图展示并要求重新确认；后台修改小区版本后，旧确认档案暂不上图，避免悄悄移动公开位置。
- 普通订单日期筛选覆盖后续服务场次；拼单始终保留完整任务包。
- 服务端拒绝缺失/无效抢单坐标，最终接单事务再次验证各成员位置和最新服务半径；详情页也补充真实定位输入。
- 指定预约创建与接单/排班修改共享宠托师版本锁，并在创建事务中重新检查全部服务时段。待支付占用期限与已有30分钟支付期限一致；已发起但未确认关闭的支付继续占档，等待现有支付巡检核实，避免晚到成功回调与新预约冲突。
- 接单已提交后通知/消息失败不会把接单改报失败；本人重复请求可确认已接单，通知沿用既有事务出队重试机制。

## 验证与实际边界

自动化覆盖包括小区人数/任务跨页聚合、整团语义、后续日期、位置输出白名单、个人公开开关、无效定位、并发指定预约、通知失败、标记稳定性及前端请求乱序。

微信原生地图无法由 Node 测试真实渲染。仍需微信开发者工具与 iOS/Android 真机确认浮层遮挡、标记点击、半屏拖动、风险模态、定位授权、动画性能及真实支付链路；当前没有这些验证的成功结论。

首版城市数据在服务端受控查询后由客户端按地图视野过滤和聚合；单次候选预算为2000笔公开待接订单/2000位已公开人员，公共小区最多1000个，超出时提示使用列表，不冒充全量。下一阶段可改为按小区/城市的服务端候选索引和视野查询，进一步降低大规模订单的装配开销。

尚未实施方案中的全部增强项：地图页直接按完整宠物、服务类型及全部时段预计算人员可约人数；跨页面持久恢复地图视野；后台逐笔修订未匹配订单的小区关系及小区合并/拆分工具；精细化的卡片退出补位与新任务手动排序提示。当前人员卡片明确写明地址与档期待确认，最终沿用现有创建页及服务端校验，不伪造可约结果。

本说明记录已落地的首版能力及限制，不替代上线前的真机验收。
