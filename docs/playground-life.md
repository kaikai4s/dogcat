# 乐园陪伴、养成、菜园和多人乘车

## 使用入口

场景顶部的“爱宠”打开自己的宠物列表；点宠物或列表项后显示精力、饱腹、水分以及疲惫值（100－精力）。原“跟随宠物”现在叫“镜头跟随”，只控制镜头。新增“让它跟我走”才是宠物跟随角色；可同时带多只宠物，“取消跟随”让该宠物在当前位置附近活动。点击地图发出单独移动指令，也会取消对应宠物的跟随。

“爱宠”“庭院装饰”和待处理申请共用顶部工具栏，窄屏空间不足时自动换行；低状态提醒和宠物列表按顺序排在工具栏下方，不再各自使用固定高度叠放。打开菜园、设置或申请面板时隐藏顶部工具栏。

宠物根据主人最新的合法位置绕开房屋和围栏，经院门进出；主人的好友及临时访问权限同样用于跟随寻路。新一轮追随先等待约700毫秒，期间继续收到位置更新也不会反复延后出发；连续追随时保持行走衔接。速度随距离在7～16米/秒之间调整，停在身边约2.5～3.5米范围内，以2米/秒在安全的小范围走动。客户端保留宠物当前绘制位置，逐帧加减速，沿可通行路线追上云端位置；慢网导致较大偏差时也步行追上。只有旧位置因新围栏等变化失效时才允许安全位置恢复。

现有角色100毫秒目标移动上报保持；跟随路线最多约600毫秒重规划一次，并且主人移动不足2米时不重复发布。推送的宠物运动记录走增量更新，不重建庭院、画布或下载全部素材。多人、慢网和复杂围栏下仍需真机测试实际跟随延迟。场景昵称去掉背景矩形，使用细浅色描边保证文字可读，保留原有名字避让。

## 状态和照料

三个状态均为0～100，基于云端时钟计算，离线后继续变化，重新进入不会恢复满值。不会死亡、丢失档案或因为状态低而禁用角色控制。

| 状态 | 每小时自然消耗 | 恢复方式 |
| --- | --- | --- |
| 精力（疲惫的反值） | 8 | 回本种宠物的窝，抵达后每秒 +0.16，最长15分钟 |
| 饱腹 | 12 | 喂零食立即 +25；或去本种宠物的碗，抵达后每秒 +0.24，最长5分钟 |
| 水分 | 18 | 去自家喷泉饮水，抵达后每秒 +0.3，最长7分钟 |

未到站不会提前恢复，改换活动会结算已完成的恢复；重复请求不会再次计算。休息、进食、饮水时停在设施前的可通行位置。没有独立趴卧、进食和喝水图集时沿用现有站立帧。

猫狗有各自的碗，庭院添粮同时补满两只碗。去碗边吃饭先原子预留25份粮，满碗可安排4次进食；中途取消不退已经预留的这一份。零食为乐园免费照料，每只宠物间隔60秒，已接近吃饱时不能再喂，须在5米内且无遮挡。乘车时只能给确实同行的宠物喂食，其他活动需先下车。

任意状态 ≤20 时，在乐园顶部显示对应宠物的照料提醒，点提醒选中它。一次低状态期间只更新提示，不反复打断控制；恢复到阈值以上后再次降低会再提醒。提醒覆盖未选中的自家宠物，状态面板每秒刷新。本版提醒在打开乐园时出现；不冒用微信订阅权限，也不声称关闭小程序后仍能主动推送消息。

宠物位于自家庭院内时，精力、饱腹或水分 ≤20 会自动前往窝、食碗或喷泉，优先处理最低的可恢复数值，到达设施后逐步恢复，接近满值后继续自由活动。自动照料由服务端随场景心跳及快照推进，邻居也能看到；不依赖主人选中宠物。庭院内的跟随会被低状态照料打断，乘车和庭院外不会自动寻找恢复设施；空碗不扣粮、不恢复饱腹，其他可用照料仍可进行。

排泄停顿与地面痕迹同样由服务端生成并同步给所有观察者：院外便意 ≥40 等待2分钟，尿意 ≥20 每30～60秒检查排泄，满100时在原地排泄。排泄停顿3秒，沿原轨迹继续移动；车内排泄同步车辆污渍。每只宠物最多保留12条、24小时内的痕迹，客户端最多绘制60条；共享便便拾取后原子删除对应痕迹，不发放肥料或奖励，刷新或重进不会再次出现。没有人在场景中时不运行后台定时器，下次进入或查看快照时推进。

## 一起坐车

跟随宠物会与主人一起上车。为避免隔墙传送，上车前所有跟随宠物须到车辆12米内、且与车辆之间无遮挡；尚未跟上的宠物会提示稍等。车内不在原地画出宠物，仍可用“爱宠”查看状态。下车时重新出现在主人身边，并继续跟随。

车主停车后走近其他在线角色7米内，出现“邀请某某上车”；步行角色靠近已停车的他人车辆7米内，出现“申请乘坐某某的车”。申请进入已有的私有申请信箱，顶部“待处理申请”或设置里的申请面板可同意、婉拒。申请60秒内有效，同意时再次检查双方会话、小区、车辆实例、距离、停车状态和座位。无需先加好友。

一位司机最多带3位乘客，每人可带自己的跟随宠物。乘客依照同一车辆实时坐标显示，不能改变方向、路线或车速；只保留低频心跳，车辆监听持续实时刷新。乘客可“与宠物一起下车”，不会影响其他人；司机选择“一起下车”时所有乘客及各自同行宠物在同一事务中下车。车旁安全空间不足时请换开阔位置。

司机重进同一小区保留驾驶和宠物乘坐状态。乘客重新进入乐园时自动下车，不占用旧座位；司机切换小区先让乘客下车，再把自家车辆入库。拆除庭院在同一个事务里释放本车乘客，随后删除车辆，避免留下无车可下的乘客。断网司机的车停留在最后确认的位置，乘客仍能自行下车。

## 庭院植物装饰与会员奖励

种植已改为纯装饰：在自己的庭院和新地皮内选草块，可获得耕地、开垦、浇水、种植及恢复草坪。没有固定12块地、种子库存、种植经验、出售或收整收益。成熟植物持续展示，不出现收获徽标；走近可收整。

作物、建筑和新地皮通过现有会员等级解锁，不扣代币。后台可管理素材、删除配置并指定允许的会员等级。洗车、便便举报、纠纷处理和每周处理奖励计入现有会员积分与流水，服务端校验真实事件和重复请求。具体金额、规则、迁移和部署见[庭院装饰与会员解锁](playground-farm.md)。

## 数据集合与索引

本轮宠物陪伴、状态、农耕和多人乘车没有新增集合，因此 `cloudfunctions/api/config/constants.js` 的集合列表无需增加表名。

| 数据 | 集合及存放位置 |
| --- | --- |
| 宠物状态、跟随、照料、同行标志 | `pet_playground_plots` 的 `resident_<用户摘要>` 文档 |
| 庭院操作幂等收据 | `pet_playground_plots` 的 `garden_<地块实例摘要>` 私有文档 |
| 会员奖励流水 | 既有 `point_logs`，同一事务更新用户积分和会员等级 |
| 公开菜地和作物 | `pet_playground_plots` 的庭院文档，字段 `farmBeds` |
| 车辆、司机及乘客状态 | `pet_playground_plots` 的车辆及角色文档 |
| 邀请/申请乘车 | `pet_playground_plots` 的 `social_<用户摘要>` 文档，实时通知投影到 `pet_playground_live` 的本人信箱 |
| 实时角色、宠物、车辆和作物 | `pet_playground_live` 的小区场景分片 |

除下列场景索引，还需在 `pet_playground_disputes` 创建新登记的场景时间、处理人时间索引，字段见庭院装饰文档；已有相同字段和顺序的索引不必重复创建：

| 集合 | 索引名称 | 字段顺序和方向 | 唯一 |
| --- | --- | --- | --- |
| `pet_playground_plots` | `idx_playground_map` | `communityId` 升序 → `kind` 升序 → `_id` 升序 | 否 |
| `pet_playground_live` | `idx_playground_live_scene` | `kind` 升序 → `communityId` 升序 | 否 |

手动创建路径：微信开发者工具 → 云开发 → 选择正在使用的云环境 → 数据库 → 选择集合 → 索引管理 → 添加索引，按表中顺序添加字段、选择升序，类型选择非唯一，保存后等索引创建成功。庭院收据通过固定文档 `_id` 读取，使用集合默认 `_id` 唯一索引。

上述两个自定义索引已登记在 `cloudfunctions/api/handlers/initData.js` 的 `REQUIRED_INDEXES`，不是在 `constants.js` 中登记。`constants.js` 仅列出集合名称。部署云函数不会自动运行数据库初始化；若通过初始化入口创建，仍需检查索引结果及控制台状态。私有集合继续禁止客户端读写，实时集合沿用 `cloudfunctions/api/database-rules/pet_playground_live.json` 的权限规则。

## 素材和上线

现有素材足够运行全部功能。菜地、作物阶段提供Canvas绘制；车头沿用现有24帧图集。用户随后提供的背面24帧已处理为 `output/blue-car-drive-nw-v2/cloud-upload/drive-nw-v2.png`，上传到 `packagePlayground/2d/baseImage/car/drive-nw-v2.png` 后，由 `VEHICLE_REAR_ATLAS` 配置加载。左上显示原帧，右上只对当前帧做一次水平镜像，禁止把车头垂直翻转充当车尾。静止保留最后实际行驶方向。图集上传和接入细节见[车辆素材说明](playground-vehicles.md#左上与右上车尾图集)。

图集未上传或下载失败时，车尾使用 `utils/vehicle-rear.js` 中的等距投影绘制兜底并重试下载。接近水平行驶时保留前后视角，避免摇杆轻微抖动或浮点误差引起车头/车尾闪换。

需要更统一的美术风格时，可补充：

1. 蓝色轿车左上车尾24帧已由用户提供并完成处理，无需重复提供；右上通过镜像适配。
2. 六种作物的萌芽/幼苗/生长/成熟4阶段，透明PNG、单格256×256、根部位置一致；土壤提供荒地、开垦、湿润三种菱形地块。完整生成提示词、尺寸和对齐要求见[菜园素材提示词](playground-farm-art-prompts.md)。已接入云端PNG图集；下载失败时沿用Canvas绘制。
3. 猫狗趴卧休息、进食、饮水的独立透明动作帧图，以及可选喂食/浇水/收获动作。只接入用户实际提供的动作，不从单张站姿伪造缺失动作。

部署最新 `cloudfunctions/api`，然后重新编译/上传小程序。复用已有 `pet_playground_plots`、`pet_playground_live` 及实时权限，无需新建集合或放开客户端写权限。旧客户端保留原有移动接口，但新功能必须前后端同时更新。

已覆盖云端及小程序联动模拟测试；上线还需双账号真机检查监听权限、冷热启动、跟随绕院门、多宠物同行、司机/乘客各自下车、跨小区/拆除、菜园小屏滚动及临界成熟时间。
