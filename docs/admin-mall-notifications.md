# 商城管理员订单提醒

## 修复原因

此前商城支付成功仅更新订单与财务流水，没有生成管理员新订单站内通知或订阅发送任务。后台首页待办统计也没有商城订单映射，导致已付款待发货订单不显示数量。

## 管理员设置

1. 超级管理员在「系统设置 → 订阅消息」开启订阅，并配置「管理员商城新订单提醒模板」。该模板沿用已有支付成功通知的字段：thing2 商品名称、character_string1 订单号、amount3 实付金额、time4 时间、thing5 收货地点；若未单独填写，则沿用支付成功模板 ID。必须是当前小程序已添加且字段一致的真实模板。
2. 有商城订单权限的管理员在控制台点击「商城订单订阅」，主动在微信中同意订阅。每次同意增加一次对应模板的提醒机会，与普通订阅中心相同；不能在后台替管理员自动授权。
3. 每位需要微信提醒的管理员都要用自己的账号授权。模板未配置、订阅关闭或授权次数不足时，站内待办仍保留，具体微信失败原因可在系统设置的订阅投递记录中查看。

## 行为

- 只有支付到账的商城新订单产生提醒，未付款订单不提醒发货。通知和订阅发送任务与商城支付入账在同一事务中保存；重复回调不重复生成。
- 只有启用且有 `adminMall.listOrders` 权限的管理员会被选作微信接收人。发送及重试前再次核对管理员身份、权限和订单待发货状态。
- 微信任务提交后立即尝试发送，临时失败沿用现有定时重试。微信发送失败不撤销已到账支付或站内通知。
- 商城新订单站内通知进入通知待办。订单发货或进入售后后，该新订单提醒按当前订单状态视为已处理，不再占用未读待办数。
- 首页「商城订单」显示待发货与待处理售后总数；一笔订单只计一次。待处理售后状态为 applied、return_shipped、pending_manual；处理中退款和等待买家寄回不占管理员待处理数量。
- 商城专属管理员通过有权限的商城接口取得数量，无需全局 dashboard 权限。已有待处理订单同样计入红点；不会对上线前已付款的历史订单追发微信新订单提醒。

需更新 api 云函数和小程序。自动化测试使用模拟微信发送接口，正式发送仍受真实模板、用户授权及微信额度约束。
