# AI 助手服务入口兼容修复（2026-10-25）

现象：AI 宠护助手发送问题后显示「AI 服务暂不可用，请稍后重试」。

本地确认的原因：项目锁定 `wx-server-sdk@4.0.2`，该服务端 SDK 提供 `cloud.ai()`，没有 `cloud.extend.AI`。旧问答处理器只检查后者，在调用模型前直接返回上述错误。宠物心声使用同一旧入口，也会静默回退预设文案。此前测试只模拟旧入口，未覆盖真实安装 SDK 的接口形态。

修复：问答与心声优先通过 `cloud.ai()` 获取 AI 客户端，兼容已有扩展入口；保持 `hy3` 模型、登录、限流、宠物归属校验和提问/回答内容检查流程。SDK 不支持 AI 时提示管理员更新云函数及依赖。

随后用户反馈 HTTP 404。进一步核对官方 [wx-server-sdk 调用指南](https://docs.cloudbase.net/ai/model/wx-server-sdk-access) 后确认，`hy3` 的调用组合是 `cloud.ai().createModel('cloudbase')`，不能沿用旧的 `createModel('hunyuan')`。安装的 SDK 会将两者分别路由到 `/cloudbase/chat/completions` 和 `/hunyuan`；前一轮只修入口，未修问答路由。现已改为 `cloudbase`，删除心声创建模型失败时回退旧路由的逻辑，问答返回的 `source` 也与实际模型统一为 `hy3`。官方成长计划文档说明 `hy3-preview` 已下线，不应改回该旧模型。

验证：新增测试使用真实安装 SDK 的模型适配器和结果解析器，仅替换底层请求为本地合成响应，不向云端请求或产生模型费用；测试服务只接受 `/cloudbase/chat/completions`，旧路由直接返回 404，避免任意路径都返回成功的模拟再次漏检。覆盖正常问答、心声、登录/资料权限、内容检查、空回答、模型失败及 SDK 缺失提示。

环境核对：用户要求检查的是 `cloud1-5gnhqn4t0554c1d9`（体验/开发环境）。已在该环境控制台确认 `hy3` 开关开启，生产环境与该环境相互独立。

发布：当前排查目标是 cloud1，应在 `cloud1-5gnhqn4t0554c1d9` 对整个 `cloudfunctions/api` 执行「上传并部署：云端安装依赖」。正式版使用 `production-d2g5jx277f41a81a6`，需要发布时应单独更新对应环境。本次兼容修复只修改后端，无需为此单独重新发布小程序。部署后在对应版本发送普通服务咨询，验证真实模型响应；本地验证和模型开关开启均不能证明线上模型调用成功或额度充足。此次未执行线上部署或检查额度。
