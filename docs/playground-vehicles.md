# 庭院车辆

所有用户先使用同一辆蓝色轿车，每个已建庭院只有一辆车，车辆操作按账号归属校验。已有庭院首次进入共享场景时自动补车，不要求庭院主人在线。

## 使用

1. 点击自己车位上的车，选择“启动车辆”，车移到自家院门外的公共空地。
2. 角色走近车（6米内且没有围栏阻挡）后可“进入车辆”。上车后隐藏角色，车上显示角色昵称；空车显示“某某的车”。
3. 摇杆直接驾驶，显示方式、左右手和透明度与角色共用。也可点击自己的车选中，再连续点击空地更换驾驶目标。单指拖图保留选中；缩放、打开设置等取消选中。
4. 点击驾驶中的自己的车，选择“下车”。角色出现在安全的公共空地，车辆留在原处；角色在车旁可再次上车或“车辆入库”。入库只移动车辆，角色留在原地。
5. 设置中的车辆最高速度默认是跑步的2倍（28米/秒），可调到5倍（70米/秒），推杆幅度控制当前速度。设置保存到账号，重新进入仍生效。

车辆只能在庭院外行驶，包括好友和自己的庭院。启动、入库是车位与院门外之间的状态切换，不会穿越栅栏播放路线。司机退出后保留车内状态和确认的位置，其他人看到昵称及离线提示；重新进入同一小区继续在车内。切换访问其他小区时，原小区车辆自动入库，访客以角色进入，不复制车辆。拆除庭院同时移除车辆，重建后获得新车位状态。

## 手动上传素材和部署

仅上传 `output/blue-car-drive-v2/cloud-upload/drive.png`，目标云目录：

```text
packagePlayground/2d/baseImage/car/drive.png
```

图集为4列×6行，共24帧，1024×1536像素，每格256×256，透明RGBA，落点230/256。用户已提供上传后的 File ID，与 `miniprogram/packagePlayground/utils/vehicle-assets.js` 中的配置一致，使用该云端图集。后续更换路径时修改该配置。单帧、源图、GIF、ZIP均不需上传，全部放在小程序包外的 `output/`。

车库和车位沿用用户提供的 `baseImage/car_house.png` 与 `baseImage/car_road.png`。车辆图集使用直接云文件加载，保留alpha和原图尺寸，不经过装饰图片的去白或方形缩放。未下载成功时显示临时蓝色车辆标记并重试；上传完成后重启小程序清除下载缓存。

素材由已有24帧裁剪、去白和统一尺寸而来，没有新增朝向或重绘车轮。向右使用镜像；停止使用首帧，行驶相位随实际距离推进。

本次需要重新部署 `cloudfunctions/api`，并重新编译/上传小程序。复用已有 `pet_playground_plots` 私有集合、`pet_playground_live` 公共投影和 `idx_playground_map` 索引，不新增车辆集合、索引或客户端写权限。

## 同步和校验

车辆记录使用独立的 `vehicle_<账号散列>` 主键，绑定当前庭院实例。公共投影不含openid或session。角色与车辆在同一事务保存位置，服务端按保存的车速限制距离，逐段验证实际路线；角色移动不能伪装成车辆移动来提高速度。上下车操作与移动上报串行，迟到的上下车前数据被拒绝。车辆推送走轻量更新，不重新处理全部宠物、庭院或地图缩放。客户端采用插值和最多180毫秒的受碰撞约束外推，慢网、冷启动和推送延迟仍需真机双账号验证。

需在真机检查：车库/车位摆放、透明边缘、常显和长按两种摇杆、左右手、默认/最高车速、围栏碰撞、上下车与入库、两账号名称和移动同步、离线后原位恢复。模拟测试不能确认实际云文件权限、资源内容或端到端延迟。
