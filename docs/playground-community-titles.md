# 庄园维护小区与用户头衔

庄园首页及全屏场景的小区选择器共用后台“小区地图管理”的已启用小区。维护后的小区即使无人入住也可选择；用户可按城市、名称搜索，无需先地图定位。选择时提交公共小区 ID，服务端重新读取名称和公共坐标。新维护小区的庄园场景 ID 根据公共小区 ID 固定生成，修改名称不会新建另一座庄园。

“申请新增小区”支持手工填写或地图选点后填写公共名称、城市、行政区。申请仅保存这些公共信息，不上传家庭坐标、楼栋、门牌。后台在“小区地图管理 → 待维护”核验公共点，保存并启用后，小区进入庄园目录。

新增申请由服务端记录首位申请人。后台通过该申请首次创建小区时，在同一事务中为首位有效申请人发放“小区初创者”；重复申请、重复审批和关联已存在小区不会重复授予。历史申请没有首位申请人记录时，不根据后续申请猜测或补发。新功能不自动给后台直接建立、没有用户申请的小区指定初创者。

用户头衔独立保存于用户档案的 `userTitleInventory`，当前佩戴项为 `equippedUserTitleId`。庄园首页“我的头衔”和全屏场景设置“我的用户头衔”可选择佩戴或摘下，一次佩戴一项。授予不自动佩戴；用户不能通过请求自建头衔或佩戴他人头衔。小区初创者头衔仅在对应维护小区的场景内显示，在其他小区访问时隐藏。佩戴更改同步到在线角色公共投影，不公开申请人身份字段。

历史庄园保持原场景身份和入住数据，在选择器标记“历史庄园”。不会按相似名称自动合并到公共小区，避免覆盖庭院、占地或邻居关系；已有住宅仍须先拆除才可迁入另一小区。旧版用户接口保留历史小区数据兼容；新版地图选点只提交申请，不直接把未维护小区加入新目录。

选择器将列表和申请表分屏展示，提供骨架加载、独立错误重试、申请结果提示与底部固定操作区。翻页沿用已提交的城市和搜索词，对重叠结果去重；申请提交期间禁止切换查询或关闭，避免丢失反馈。停用、删除或公共坐标不完整的维护小区不会从用户保存的历史资料重新进入可选目录。

头衔面板提供当前佩戴预览、所属小区、佩戴中状态和操作反馈。佩戴请求若响应丢失，会重新读取服务端确认状态。场景展示带小区场景编号校验，旧请求晚于切换庄园返回时不会覆盖当前庄园。两个面板采用轻量入场动效，并尊重系统减少动态效果设置。

兼容 CloudBase 对普通对象按叶子字段更新的行为：常住小区与在线角色头衔均显式完整替换，支持原值为 `null` 的首次写入，并清除切换时过期的小区字段。保存接口返回事务中实际写入的小区信息，避免并发改名时返回旧快照。目录读取优先使用当前公共档案，异常历史坐标仅跳过该历史项，不影响其他小区；数据库读取错误仍向上传递。申请成功后的目录刷新独立进行，避免刷新缓慢锁住操作；已维护小区按当前公共名称重新查询。

头衔读取在同一事务内获取用户佩戴项和角色场景，响应同时携带场景会话与角色版本。页面拒绝旧会话、旧角色版本的延迟响应，画布也保留已应用的头衔版本，防止旧实时快照重新显示已摘下的头衔。庄园首页按页面生命周期和请求序号处理加载结果：旧刷新不能覆盖新刷新或刚保存的小区，保存期间不重复提交，隐藏页面后的旧结果不会更新界面、弹出提示或触发跳转。

启用需部署 `api` 云函数和新版小程序，无需新增数据库集合或开放客户端写权限。本次开发未部署到线上，也未追溯修改既有用户、申请或庭院。
