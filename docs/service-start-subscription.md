# 服务开始订阅通知

## 后台配置

管理员后台 → 系统设置 → 订阅消息：

- 服务开始模板：填写微信「开始服务通知」模板编号 71479 对应的模板 ID。
- 服务进度模板：如原先使用包含 thing9、thing4、character_string5、thing10、date3 的通用进度模板，将该 ID 配置在这里。提前开始申请及答复、即将到达、超时未开始提醒使用此项。
- 前往服务提醒：使用独立的 19425 服务订单提醒模板；未配置时记录跳过，不回退到服务进度或服务开始模板。

模板 ID 均在后台保存，代码中不设固定值。71479 字段如下：

| 字段 | 内容 |
| --- | --- |
| character_string1 | 订单编号 |
| thing2 | 服务已开始，毛孩子正被贴心照顾 |

## 发送和用户授权

正式开始服务时，订单状态更新与通知入队在同一事务中完成，通知发送给下单用户，点击后进入该订单详情。每场服务有独立通知标识，重复操作不会重复发送，后续场次可再次发送。

提前申请、即将到达、超时等场景不会使用开始服务模板。未配置服务进度模板时，该类微信通知记为跳过，现有站内提醒保持原流程。历史队列中实际开工通知会转换为新字段，其他旧 serviceStart 记录会跳过发送并保留原因。

用户可在下单、支付、订单详情或订阅中心同意服务开始通知。更换模板 ID 后需用户重新同意新模板。宠托师订阅的是服务进度或前往服务提醒，客户订阅服务开始通知。

## 发布和验证

部署 api 云函数并更新小程序，配置好模板后完成一次微信真机验收：客户授权 → 宠托师按要求消毒打卡 → 正式开始服务 → 客户收到开始服务通知并可打开订单。回归测试使用模拟发送接口，不能替代微信实际送达验收。
