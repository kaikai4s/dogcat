# 角色与宠物专属形象定制

## 使用流程

1. 用户从「宠物乐园 → 专属形象定制」或庄园左上角齿轮内进入。乐园成员卡片还可直接「为某只宠物定制形象」。选择「我的角色」或自己的具体宠物，上传1～6张JPG/PNG参考照片（每张不超过5MB），填写特征后提交。
2. 管理员进入「管理后台 → 营销与会员 → 乐园形象定制」，查看申请对象、参考照片和说明。照片不足可填写原因退回；用户可以取消尚未完成的申请。后台的照片预览使用短期授权地址，用户参考照不进入公共场景数据。
3. 管理员自行根据参考照制作动作素材。此功能自动完成上传、格式校验、唯一绑定和场景更新；不自动将参考照片生成为动作。
4. 打开对应申请，选择完成的24帧图集，先检查循环预览，再点「上传并发布专属形象」。程序自动上传云存储并绑定，管理员无需复制File ID，不能在发布时改选其他用户或宠物。
5. 申请完成后，申请对象及同场景邻居会看到专属形象。客户端异步加载图集，下载期间保留默认形象，失败自动重试。角色位置、宠物路线、选中状态与手动缩放保持原逻辑。没有庭院时仍可申请，之后建好庭院进入场景时使用已绑定形象。

## 动作图集要求

| 项目 | 要求 |
| --- | --- |
| 格式 | 静态透明RGBA8 PNG，关闭隔行扫描，不支持APNG |
| 排列 | 4列 × 6行，24格全部有动作，从左到右、从上到下 |
| 每格尺寸 | 128×128、256×256或512×512，所有格子统一 |
| 图集总尺寸 | 512×768、1024×1536或2048×3072 |
| 大小 | 每张不超过8MB |
| 锚点 | 脚底在每格高度的460/512处（89.84375%），各帧脚底与身体比例一致 |
| 待机 | 使用图集第1帧；应选适合停留的站姿 |
| 角色奔跑 | 可另传同规格的24帧奔跑图集；未传时使用行走图集按移动节奏播放 |
| 朝向 | 沿用现有左前方素材规范，向右时镜像；此次未增加多方向图集 |

后台通过`wx.chooseMedia`从相册选择图片，指定`sizeType: ['original']`，不再使用`wx.chooseMessageFile`，此入口无需新增「选择文件」隐私声明；媒体选择仍使用项目已有的相应隐私声明。先将透明PNG原图保存到手机相册，选择时使用原图，请勿使用截图或聊天缩略图。客户端检查实际图片格式、大小和尺寸；若手机相册或传输过程已把图片转成JPG、改变尺寸或丢失透明度，需要重新保存原始PNG，不会自动转码或压缩。服务端检查PNG结构、CRC、解压长度、尺寸、透明通道和24格非空；不会自动修复缺帧、腰部缺块或错误步态。建议选256像素单格，512像素单格会增加手机纹理内存。自定义图集仅在需要绘制时加载，最多两个并发加载，解码缓存以64MB像素预算限制；超出预算暂用默认形象，移走后逐步释放旧缓存。

## 唯一绑定规则

- 角色按账号的OpenID派生唯一场景角色ID；宠物按真实数据库`pets._id`绑定。昵称、宠物名字和列表顺序不参与归属判断，同名的两只「豆豆」完全独立。
- 每条申请创建时固定账号、对象类型和对象ID。发布时重新核对用户有效性、宠物归属、删除状态、当前申请和上传批次。旧批次、已取消申请不能发布，失败的事务不会留下部分绑定。
- 一个目标同时只能有一条活动申请。更新形象需要该对象重新申请，旧形象在新形象成功发布前继续有效；取消或退回新申请不清除旧形象。
- 服务端对解码后的RGBA像素计算SHA-256，忽略全透明像素的隐藏RGB。相同像素图集即使改名、改PNG压缩方式或滤波方式，也不能跨账号、跨宠物、跨角色重复绑定；并发发布由数据库事务排他处理。原有素材被替换后，内容归属锁仍保留，不能再分配给其他对象。该检查不判断改色、缩放、错位或重画后图片的视觉相似性，制作方仍需为每个对象提供独立设计。
- 最终素材由云函数复制到`packagePlayground/custom/{targetKey}/{requestId}/{action}-{digest}.png`。它与管理员可写的临时上传区分开，发布后的目录必须禁止客户端覆盖或删除；用户和管理员客户端也不能直接改绑定集合。
- 未完成上传产生的临时文件、已取消申请的照片以及事务拒绝前已复制的孤立文件，暂不自动清理，避免误删正在处理或已发布的素材。后续清理须以申请状态和绑定记录为依据；不能删除历史内容归属锁。

## 首次上线配置

本次仅修改项目文件，没有部署云函数或修改云端规则。需在实际测试/发布使用的环境完成以下步骤，开发环境与正式环境分别配置。

1. 上传并部署新版`cloudfunctions/api`，重新编译/上传小程序。完成的动作图集不放入小程序代码包，由后台从相册选择PNG原图后上传云存储。
2. 创建私有集合`pet_playground_appearance_requests`和`pet_playground_appearance_bindings`。分别在集合自定义权限中使用`cloudfunctions/api/database-rules/`下同名JSON，均为客户端不可读写。申请只能通过云函数按所有者或管理员权限访问。
3. 申请集合新增下列3个**非唯一**索引；绑定集合依靠默认唯一`_id`，无需另加唯一索引。数据库初始化已包含新集合与索引，使用现有初始化入口也可创建。

   | 索引名 | 字段顺序（全部升序） |
   | --- | --- |
   | `idx_appearance_owner` | `ownerOpenid` → `_id` |
   | `idx_appearance_owner_status` | `ownerOpenid` → `status` → `_id` |
   | `idx_appearance_status` | `status` → `_id` |

4. 后台已启用分组权限时，为制作人员分配「乐园形象定制」下申请列表、查看照片、上传图集、发布专属形象等权限；退回权限可独立分配。超级管理员直接可用。服务端逐操作核验权限，前端隐藏按钮不作为安全边界。
5. 配置云存储权限，**合并到已有规则，不要直接替换整个项目规则**。本功能的表达式示例在`cloudfunctions/api/storage-rules/playground-appearance.fragment.json`，只描述本功能目录；直接整份替换会拒绝其他业务文件的读写。规则语法依据[CloudBase官方云存储安全规则](https://docs.cloudbase.net/storage/security-rules)中的`resource.path`、`resource.openid`和正则`.test()`。

   | 路径 | 客户端读取 | 客户端写入/删除 |
   | --- | --- | --- |
   | `playground-appearance/references/` | 仅文件创建者；管理员通过已鉴权API取得短期照片地址 | 仅文件创建者 |
   | `playground-appearance/staging/` | 仅文件创建者 | 仅文件创建者，发布还需管理员权限与申请批次 |
   | `packagePlayground/custom/` | 已登录玩家 | 一律禁止；只有云函数服务端写入 |
   | 其他已有目录 | 保留原规则 | 保留原规则 |

   合并方式：本功能目录使用示例条件，其他路径才允许进入原有条件分支。尤其不能让原来的「已登录均可写」分支再次放行`packagePlayground/custom/`；参考照也不能落入原来的公开读取分支。云函数服务端SDK不受客户端安全规则限制，因此仍可校验、复制素材及生成管理员短期照片地址。

## 部署后的验收

用两个账号建立同名宠物：A为自己的豆豆申请，管理员发布后仅A的对应宠物变化，B可以在同场景看到变化，B的豆豆与A的另一只同名宠物保持原样。再申请角色定制验证不影响宠物。将同一图集改名或重新压缩上传给B，应收到禁止重复分配提示；取消申请、删除目标、重新准备上传批次后，旧上传均不可绑定。普通用户、未分配发布权限的管理员、跨用户照片读取和直接覆盖已发布文件都应被拒绝。最后测试退后台恢复、重新进场、离线邻居形象和断网后图集重试。

本地自动测试覆盖绑定、并发、权限、PNG内容校验、上传错误与绘制行为；真实云端规则、SDK权限和手机Canvas显示仍需要完成以上两账号验收。

## 上传后场景提示 Cannot create field 'id'

如果提示 `Cannot create field 'id' in element {appearance: null}`，原因是旧实时记录的形象为空，SDK将普通对象更新展开为 `appearance.id` 等字段，数据库无法在`null`下面创建字段。它与图片大小、网格尺寸或相册权限无关。

实时场景现在通过`db.command.set`完整替换单个实体记录，保留同一分片里的其他玩家和版本顺序校验；发布时也完整替换申请、绑定和用户/宠物档案中的形象字段。兼容已有空值，并在更换为仅行走图集时清除旧奔跑图集，避免残留旧字段。

部署新版`cloudfunctions/api`（上传并部署：云端安装依赖）后，退出并重新进入乐园；重新进入或场景快照会从已保存的档案重新发布实时记录。之前已显示发布成功、仅场景同步失败的形象无需重新上传，不需要清空集合、重建索引或手动修改旧空值。本地回归使用与CloudBase一致的对象更新展开语义，覆盖空值兼容、再次发布、重进场景、版本顺序和分片内其他玩家保留。
