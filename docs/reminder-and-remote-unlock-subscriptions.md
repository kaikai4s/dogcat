# 服务订单提醒与远程开门请求

后台 → 系统设置 → 订阅消息，分别配置微信后台提供的模板 ID。代码不写死模板 ID。

## 宠托师服务订单提醒（19425）

配置位置：前往服务提醒模板。

- time3：当前场次北京时间段，例如 10:00~12:00。
- thing4：服务地点摘要，最多 20 字；完整地址在订单中查看。
- short_thing6：宠物类型，最多 5 字，支持猫、狗及多宠组合。
- thing7：宠物名字，最多 20 字。
- thing5：请按时前往，完整地址及照护要求见订单。

服务前 1 小时内触发，沿用原流程对开始后 30 分钟内尚未开始的任务补提醒。接收人为指派宠托师，点击进入服务执行页。多天订单按当前场次提醒，同一场次并发扫描不重复发送。该模板不再回退使用服务进度模板。

## 远程开门请求（24826）

配置位置：开锁请求模板。

- character_string1：订单编号。
- thing4：宠托师请求远程开门。
- thing10：请核实到访人员后，在门锁应用远程开门。
- time5：本次请求的北京时间（日期及时间）。

仅绑定宠托师可发起，通知发送给下单用户并进入订单详情。保留两分钟请求间隔，增加并发校验和事务入队。通知只提示处理，不执行门锁开门。失败进入现有重试队列，重试保留原请求时间。

## 发布与授权

部署 api 并更新小程序后配置两个模板 ID。宠托师通过接单入口或订阅中心授权服务订单提醒；下单用户通过支付、服务中订单详情或订阅中心授权远程开门通知。更换 ID 后须同意对应新模板。

历史旧格式待发记录不能准确转换为新模板的字段，保留记录并标记跳过原因，避免发送误导性提醒。真实送达需在微信环境完成授权及触发验收；自动测试使用模拟发送接口。
