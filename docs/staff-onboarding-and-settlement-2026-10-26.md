# 宠托师保证金、培训与后台收益结清

## 行为

- 支付保证金后最多查询三次服务端状态；进入培训页或“我的”也会核对当前未支付保证金。服务端向微信查询原支付单，校验商户号、AppID、单号、金额与交易号后，复用原入账事务。查询失败保留待核实状态，历史没收/退款记录不会恢复成已缴纳。
- 培训视频放在答题之前。全部启用视频观看完成且资料审核通过后才返回题目；答题默认折叠。直接提交未解锁的答题也会被服务端拒绝。未配置可播放视频时，应先在后台补齐视频素材。
- “我的”顶部补缴提醒分为标题、原因和金额/按钮两行区域，支持文本换行。
- 后台“宠托师管理”增加“收益转账结清”“退还保证金”和“查看转账”入口。

## 收益转账结清

1. 预览当前可提现收益和待结算、冻结、已有提现占用金额；管理员确认后发起。
2. 对确认时的收益明细建立不可变任务，按项目现有转账限额与每笔最多50条收益分组，逐笔复用提现审核、额度预占、商家微信转账和查单服务。后台结清允许处理低于普通业务提现门槛的余额尾款，但每笔仍须达到微信最低0.10元。不足时保留余额，合并其他收益后处理。
3. 每笔沿用确定的请求号与微信单号。中断后点击同一入口续办；若需要重新核对，可以清除本机续办记录，已发起的转账仍保留，并从新的可提现余额中排除。
4. 发起后收益进入提现占用，微信确认 SUCCESS 才标记已提现；未知、处理中和待确认收款均不会当作到账。失败单到财务管理查询、重试或按现有规则处理。
5. 保留原收益金额、原订单关联、提现和管理员审计记录，不删除或改写历史收益。收款微信固定为宠托师绑定的 openid。

某批返回实际转账错误时，界面显示微信原因与错误码，停止后续批次并保留当前批次续办记录。恢复时继续核对原单，不跳过异常批次。提现的元/分金额不一致时先核账；原小额单退回前也须满足收益合计一致。

当前保留项目原有单笔最高200元的限制，配置更低时按更低额度执行，单笔最低为0.10元。多条收益可自动分组；50条明细边界留下小额尾批时尽量移动完整收益合并，不能满足最低金额则明确拦截。若一条不可拆分的收益超过单笔限额，会在发起前明确拦截，需另行核对打款方案。平台和个人日额度仍按原规则限制。

## 不足0.10元的退出尾款

“宠托师管理”增加“小额尾款人工结清”。只处理全部可提现余额大于0且不足0.10元，并且没有其他待结算、冻结、收益占用或未完成提现的情形；历史未知微信单必须先查询处理，不能另行人工重复付款。普通低额收益仍可留在余额中累计。

管理员核对姓名和金额后生成待审核人工结清单，完整关联原收益与原订单，保留每笔金额。该动作只预占收益，不记为已支付，也不调用商家微信转账或占用微信转账额度。到财务管理审核，再与本人核对收款方式并完成实际付款，点击“登记尾款实际付款凭证”填写真实流水/凭证号后才记为已结清。付款前不应登记到账。待审核单可驳回并将原收益退回余额。

创建操作使用固定请求号，提交结果丢失时重用原操作；并发操作不能重复占用收益或登记支出。现有“审核提现”“确认提现付款”权限与严格双人复核规则继续适用，开启严格双人复核时审核人与付款登记人须不同。付款成功登记后立即尝试完成保证金已退款但因尾款待结清的退出；有其他待办时保留退出状态，由原定时任务继续核对。

普通管理员需增加“发起人工尾款结清”（`admin.createStaffManualTailSettlement`）权限，依赖结清预览、宠托师列表及提现列表。该权限只建立待审核记录，审核和付款登记各自需要原有权限。宠托师自己的提现记录会区分“待人工付款”“已人工结清”并展示付款凭证号。

后台财务列表和宠托师提现历史同步区分“待人工付款”“已人工结清”。续办时若原人工尾款单已驳回，明确提示收益已退回余额，重新发起需再次核对余额。

## 保证金退还与退出

管理员可填写原因发起保证金退还，随后到财务管理审核。微信支付的保证金审核通过后自动发起原路退款，使用原支付单和固定退款单号；处理中由五分钟定时任务、宠托师状态刷新或后台“同步 / 发起原路退款”继续查单。已审批未退款的历史记录也会补发，退款金额为已缴金额减去有记录的没收及已退金额。非微信原支付仍要求实际人工退款凭证。详见 [提现与保证金退款修复说明](finance-payout-recovery-2026-10-26.md)。

微信返回成功后才记录实际退款与资金流水。退款已到账但仍有未结清收益、冻结、未到账提现或其他保证金时，保留“退出待结清”，定时任务待全部处理完成后撤销宠托师身份；不会将已经成功的退款误记为未退。人工确认退款仍先核对收益与提现。普通移除身份的资金检查不再仅扫描前100条收益/提现或最近5条保证金，数据库查询失败也不会被视为已结清。

## 发布与验证

本次仅修改本地代码，没有部署云函数、发布小程序或执行真实资金操作。

更新 api 云函数和小程序后生效。普通管理员需授权新增的“结清收益预览”“结清收益微信转账”“发起保证金退还”权限；超级管理员可直接使用。真实支付、微信零钱收款确认和窄屏/大字体布局需在微信开发者工具或真机验收。

测试覆盖查单补记、金额/商户等校验、历史保证金隔离、培训解锁、分批转账、未知状态保留占用、成功到账、并发结清幂等、原任务续办、冻结冲突和退出拦截。
