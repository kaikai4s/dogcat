已加入宠物跟随、同行上下车、三项养成状态与照料提醒、6种作物与12块田的农耕系统、四向车辆显示，以及邀请/申请多人乘车。入口、玩法、数值、离线与部署说明见[乐园陪伴与农耕](playground-life.md)。

## 小区共享、离线与迁居

点击场景顶部的小区名称可访问其他小区、回常住小区、迁入当前访问的小区、拆除自己的庭院。标题使用当前实际进入的小区，长名称单行省略，显示当前小区已建庭院人数（含离线住户，不是在线人数）。访问不修改常住小区、不搬走原庭院；访问者不能在该小区认领庭院。迁入通过现有常住小区接口完成，服务端在事务中要求先拆除旧庭院。拆除需确认并核对本人当前 plotId 与所在场景，事务同时清理占地、主人记录、角色 presence 和 resident 宠物运动记录，保留 pets 宠物档案。

未建庭院和拆除后的用户只浏览场景，不发布自己的角色和宠物；enterScene 返回 hasAvatar=false，仍允许建立隐藏的浏览会话以读取邻居。旧版遗留的无庭院角色/宠物也不在公共场景显示。底部“选择小区并建造庭院”直接选小区、保存常住小区、进入选址；不依赖当前场景有宠物。已有常住小区时，也可点“在这里建造庭院”；访问其他小区且没有旧庭院时，会先确认迁入再选址。建造完成后重新进入，按保留的宠物档案恢复场景角色和宠物。

同小区读取同一份庭院、狗碗粮量、角色与宠物运动状态。别人庭院和宠物可见，但不能控制、调大小、添粮或拆除。访客的宠物仍留在原小区。首次部署后，已有庭院的宠物可由访问者请求补建共享运动记录，不要求主人先登录。

`enterScene` 建立带随机 session 的场景会话。`syncScene` 保存角色坐标、类型、朝向与在线心跳，序号拒绝迟到写入，新设备进入使旧会话失效；服务端校验移动总距离、沿途碰撞和庭院访问权限。`getScene` 按小区和游标每页100条返回脱敏数据，不暴露openid或会话密钥，用于首次进入、断线恢复和每30秒校准；不再依赖1500毫秒轮询驱动角色。

角色移动与停止变化以100毫秒为目标间隔持续上报，每个客户端保持一次在途写入，慢请求完成后立即继续；静止时每2秒心跳。云端写入后发布脱敏场景投影，客户端通过微信云数据库 watch 长连接立即接收变化，按实际收包间隔自适应插值显示邻居移动，并最多外推180毫秒补足消息间隙；外推碰到围栏立即停在确认位置。网络往返、云函数冷启动和微信推送都会带来延迟，100毫秒是发送目标而非真机端到端延迟保证。宠物共享同一条路线、epoch和云端时钟，自动活动在各端连续求值；移动、互动、大小调整和场景布局改变后推送新状态。邻居宠物名称显示“主人昵称的宠物名”，例如“凯大大的豆豆”。

移动同步失败时保留原序号和原轨迹重传，服务端通过 `ackSeq` 确认已提交的轨迹；丢失回包或实时投影发布失败不会把已保存的路线当成新移动重复计算。确认旧包后立即补发其后的新移动，网络失败按1～2秒间隔重试，本地摇杆继续响应。步行和驾驶均保留帧内实际转弯，每包最多600个轨迹点，积压路线按顺序分批补发。服务端按实际时间累计有限移动额度以吸收到包抖动，分批共享剩余额度，继续校验速度、碰撞、会话与庭院权限。新版客户端传 `reconcile: true` 时，真实非法路线只保存已验证的合法前段，直接返回最后可通行坐标及校正原因，客户端立即调整而不锁定摇杆等待全场景快照；非法坐标仍拒绝。部署此修复须同时更新 `api` 云函数与小程序，旧客户端仍保留原有错误处理。

移动距离、路径长度或碰撞校验失败时，客户端暂停输入并读取服务端已确认坐标，只校准角色和清理未确认路径，不重新进入场景、不重建画布或下载图片，也不改变镜头及缩放。短暂断网保留当前画面；监听、上报及补偿快照失败后逐步延长重试间隔，最长30秒，避免故障时密集请求。过期监听和退后台前发出的快照不能覆盖恢复后的场景。

当前架构尚未做真实云端容量压测，不能承诺具体同时在线人数。容量主要取决于同一小区同时在线、移动的用户数及云端并发和数据库配额。以每人每秒10次目标上报估算，100人持续移动会产生约1000次同步调用/秒，每次还包含数据库读写、全小区庭院查询和向同区监听者推送；实际频率会受请求耗时限制。16个分片用于分散写入和规避监听条数限制，并不代表可无限承载；同区全量广播、分片文档大小仍是瓶颈；客户端已将纯角色位置推送改为只更新角色，避免每次处理全部宠物和庭院。宠物自动活动按路线和时钟播放，不逐帧上传，能降低这部分负载。正式开放大量用户前，应按目标人数做分阶段压力测试，记录调用延迟、错误率、读写量和监听流量；进一步扩容需采用空间分区、仅推送附近实体，以及独立长连接实时服务，数据库保留低频持久化。

新增 `pet_playground_live`：每个小区16个scene分片文档承载脱敏实体，单个watch最多读取16条，避免直接监听只返回前20个实体。公共投影只含昵称、散列用户标识和场景数据，不能写入openid、session、好友申请或私有用户档案。每次发布以版本条件更新，防止迟到快照撤回移动、复活拆除实体；删除事件以墓碑推送，同格重新建造使用新的实例标识和更高版本。`mail_<散列用户标识>` 是单用户好友/申请信箱，用 `_openid` 限制只能本人读取。连接失败显示重连提示，自动重连并暂时用快照补偿，退出页面关闭监听，旧监听回调不会覆盖新场景。

场景和好友消息使用两条独立的查询监听，独立退避重连；好友消息失败不关闭场景监听，也不停止角色控制。好友消息查询显式包含 `_id`、`kind: mail` 和 `_openid: '{openid}'`，由微信安全规则替换为当前用户，满足私有记录的读取条件。数据库监听显式使用 `getCloudEnv()` 返回的当前 API 环境。连接恢复立即清除重连提示；玩家界面仅显示简短连接状态，不显示云环境ID、错误码或服务端配置；设置面板按好友访问、操控习惯和场景显示分组。

排查持续失败时必须核对环境：项目默认开发版和体验版连接 `cloud1-5gnhqn4t0554c1d9`，正式版连接 `production-d2g5jx277f41a81a6`；若使用环境覆盖，在开发者工具中检查 `getCloudEnv()` 的实际返回值。在 production 设置的集合、索引和权限不会应用到开发环境；应在正在测试的环境配置 `pet_playground_live`，原 `pet_playground_plots` 仍保持客户端不可读写。微信官方实时监听说明：<https://developers.weixin.qq.com/miniprogram/dev/wxcloud/reference-sdk-api/database/collection/Collection.watch.html>，支持单条和查询监听，不能仅凭通用断线提示认定 SDK 不支持。

截图中的 TransactionConflict 由多人读写事务竞争触发。乐园事务统一最多重试5次并退避，仍失败返回简短中文错误；宠物指令不再读写频繁变化的角色文档作为事务依赖，使用resident会话版本阻止旧页面指令，避免持续移动使宠物指令反复冲突。

## 好友与庭院访问

访问其他小区从地图中心附近的公共区域进入；中心若被庭院占用，寻找附近栅栏外的空地，不恢复上次在他人庭院内的位置。陌生人的整个庭院是角色禁入区域，门口保留在外侧；客户端碰撞及云端沿途校验同时执行。未安置庭院的用户维持只浏览状态。

走近其他角色5米内出现“添加好友”，发送后由对方同意才成为双向好友，好友可以从彼此院门进出。左上角设置中的“好友与访问申请”可处理申请、查看好友和解除好友，有新申请时场景显示待处理入口。解除好友会同时取消双方访问权限；好友访问也不能控制别人的宠物、添粮或拆除庭院。

非好友距对方院门6米内可申请访问，确认后进入主人的待处理列表。主人同意后，申请人可进出该庭院至北京时间当天24点；拒绝、过期、庭院拆除/换址后不能进入，不能通过保留旧页面延长许可。过期时若仍在院内，会返回院外。访问权限绑定庭院实例，同一格拆除重建也不复用旧许可。每人最多200名好友、100条有效待处理申请；已处理历史保留最近50条。私有好友和授权信息放在原 `pet_playground_plots` 的 `social_<用户摘要>` 文档，公共场景中不返回这些记录。

页面退到后台时暂停画布、保留场景实例，并提交当前位置及离线状态；恢复时继续原位置，避免重新下载和重生。彻底关闭后重新进入从云端已确认坐标恢复。正常离开尽力立即报离线；断网、强杀或后台请求被系统取消时，15秒心跳过期后显示离线，位置只能保证到最后一次云端确认的位置。后台终止后仍需重新加载画布，不能保证微信进程永不被回收。

宠物路线由服务端规划并保存 epoch、首次路径及活动循环，客户端按同一云端时钟连续求值。主人离线或没有任何客户端打开时不需要常驻云进程；再次查询可计算此刻位置，宠物不会回固定出生点。自动活动在当前所在庭院内，或庭院外附近区域；外部活动不进入庭院，手动命令可从自家院门进出，不能进入他人庭院。`movePet` 只接受本人实际拥有的宠物，服务端寻路。庭院布局变化时重建受旧布局影响的路线。外部活动为当前位置附近约20米内的循环，不是全地图无限漫游。客户端与云函数的 shared-motion、navigation、yard-layout 保持相同并由测试核对。

私有数据继续使用 `pet_playground_plots`，kind为presence、resident和social，复用 `idx_playground_map`（communityId、kind、_id）；禁止客户端直接读写。实时投影使用新集合 `pet_playground_live`，仅允许已登录用户读取公开scene及本人的mail，客户端禁止写入。此功能必须上传部署最新 `api` 云函数、创建实时集合并设置读取规则，再重新编译/预览小程序；未部署新版服务端会出现未知操作。正式启用前需两账号真机验证小区隔离、在线移动、断网重连、访问到期与宠物一致性。


宠物点地移动同时发出云端指令和本地预测：本地用共享庭院布局协作寻路，路线就绪即可起步，不等云端响应。云端继续校验所有权、围栏和目标，返回每只宠物的 commandSeq；客户端忽略旧指令路线，失败时仅回滚对应预测，较小坐标差在150毫秒内修正且不穿围栏。预测期间各端可能短暂存在位置差异，以云端确认为准。新路线会中断旧的本地规划，避免连续点击积压计算。寻路使用最小堆、线段与障碍精确相交检查及路线简化，每128个搜索节点让出主线程；宠物路线的分段数据按对象缓存，避免每帧重复编译。角色同步一次请求复用同一份导航，不再逐个轨迹点重建庭院障碍。

点击自己的角色会显示选中光圈，再点击地图空地按步行速度前往，目标旗帜可连续更新；点击宠物切换为宠物选中。角色仍需从获准访问的院门进出，未知区域加载完成前不能前进。单指拖动保留选中和当前路线，拖动松手不误发命令；双指缩放或打开设置清除选中提示，摇杆接管则停止点地路线。镜头定位和角色移动保留用户手动缩放。

## 自定义角色与摇杆互动

女孩只需上传 `people/girl/idle-sw.png`、`people/girl/walk-sw.png`、`people/girl/run-sw.png` 三个文件，完整云地址配置于 `miniprogram/packagePlayground/utils/character-assets.js`。行走、跑步均为4列3行、12帧、每格256像素；待机为512像素单图。帧图、预览、压缩包和原稿均保留在小程序目录外，无需作为代码上传。

建好庭院后默认显示男孩，随后恢复云端保存的角色类型，在左上角齿轮设置内“换成女孩 / 换成男孩”；只加载所选角色所需的云图片，下载失败保留原角色。摇杆默认常显，设置可开启“长按显示摇杆”，也可调节摇杆不透明度10%～100%（默认100%）和是否显示所有庭院用户昵称（默认关闭）。偏好保存在本机，重进保留；调整宠物大小、选址和打开设置时暂时收起摇杆。

设置内“习惯用手”可选择左手或右手，默认左手；常显摇杆分别靠近屏幕左边或右边，并考虑安全区及尺寸变化，附近互动按钮移到另一侧避免遮挡。切换时停止当前移动并保存偏好；长按模式保留原按压点浮动摇杆。顶部设置和返回按钮分别固定36和54像素宽，避免原生按钮默认宽度挤压小区名称。

常显模式使用所选侧边的摇杆，触摸后立即控制，松手停止；不会抢占草地拖动或宠物点选。长按模式在草地任意位置按满1000毫秒后以按压点为中心出现，长按前移动超过6像素按拖动镜头处理，第二根手指取消摇杆并接管缩放。两种模式都轻推行走、拉远奔跑，推回内圈恢复行走，松手、取消触摸和退后台停止；长按释放不会误发宠物指令。“回到角色”只恢复镜头跟随与位置，保持缩放。角色与宠物共用庭院障碍物和院门规则，未知或加载失败的区域不能穿过。

待机图使用用户提供的云文件 `people/boy/boy-walk-sw-end/boy-walk-sw-stop.png`，完整 fileID 在 `miniprogram/packagePlayground/utils/character-assets.js`。行走使用已修复腰部的云端图集 `people/boy/boy-walk-sw-end/walk-sw.png`，4列3行、12帧、每格256×256。角色图片保留原有透明度和尺寸，不执行场景装饰的去白底逻辑。当前只有左前方素材，向右时镜像，其余朝向暂沿用该造型；移动支持八方向，尚无独立的背面、正侧面动画。

奔跑使用独立云端图集 `people/boy/boy-walk-sw-end/run-sw.png`，同样12帧、256像素固定格、4列3行，锚点与行走一致。动作由原图的屈臂上身、相同头部和鞋子配合局部绘制腿部制作，包含交替支撑、屈膝回收、腾空与身体起伏；属于本地关节动画，并非AI逐帧重绘。上衣连续变形，腰部保持完整。动画相位由实际移动距离推进，撞墙停止时回到待机，避免原地跑。摇杆行程48像素，12%死区；72%进入跑步、62%退回行走，避免临界点反复切换。速度随推杆幅度递增，最快行走7米/秒、最大奔跑14米/秒；碰撞继续按最多0.2米分步检查。图集通过云存储加载，完整 fileID 统一配置于 `utils/character-assets.js`，本地PNG已移至小程序目录外的 `output/playground-local-assets-backup/` 备份；角色图片下载后保持透明度与原始图集尺寸，并复用本次进程的下载缓存。本次跑步与摇杆修改只需重新编译小程序，无新增云端接口。

角色距宠物4米内且中间没有障碍时可“摸摸”，宠物短暂停留并显示爱心。距自家碗的进食站4米内可同时添满猫狗两只碗；只有两只都满时按钮禁用。添粮调用 `playground.fillBowl`，服务端在事务中核对账号归属及 `plotId`，保存猫狗各100份粮食；新庭院从空碗开始。宠物安排去碗边进食时预留25份，抵达后恢复饱腹值；新版本会保留部分粮量，不能将75份误读成空碗。添粮不扣库存、不发奖励。失败不修改本地粮量，离开场景后不应用过期响应。

## 上线步骤

1. 上传并部署 `cloudfunctions/api`，创建 `pet_playground_plots` 集合（或由后台数据库初始化创建）。该集合设为仅云函数可访问，客户端禁止直接读写。新增全景分页查询需建立非唯一复合索引 idx_playground_map：communityId 升序、kind 升序、_id 升序。数据库初始化已包含该索引。
2. 创建 `pet_playground_live`（后台数据库初始化会自动创建），添加非唯一索引 `idx_playground_live_scene`：kind升序、communityId升序。在该集合“权限设置→自定义安全规则”粘贴 `cloudfunctions/api/database-rules/pet_playground_live.json` 的内容。不要修改原私有集合权限，不要把实时集合设为所有人可写。集合中的scene仅供已登录用户读取，mail只可本人读取，所有写入都由云函数执行。
3. 重新编译并预览/上传小程序。两个账号都重新打开乐园，让云端生成实时场景文档；在同一小区同时移动，确认对方连续移动、宠物位置一致；再验证好友申请、同意/拒绝庭院访问、跨午夜过期与重连。代码及模拟测试通过不代表生产环境的watch权限已配置或真机延迟已验证。
4. 云存储保留 `packagePlayground/2d/baseImage/` 下原有 PNG 文件，名称与 `baseImage/` 中一致。加载器直接下载云文件，缓存本次小程序进程内的临时路径，不依赖包内图片。更新同名云文件后需重启小程序以清除进程缓存。
5. 管理端 → 系统设置 → 宠物乐园地面，配置宽高并保存。默认 2240×2240 米，支持 224～11200 米的整数。重新进入乐园生效；不能缩小到已有房屋之外。

## 使用

单指拖动，双指缩放。默认不选中宠物，点击地图上的自家宠物后显示选中光圈、吃饭、回窝休息、跟随和大小调节；角色靠近选中宠物时可“摸摸”。选中后直接点击地图发出移动指令，无需额外按钮；保留选中，可连续点击更换目标。目标立即显示旗帜，本地路线尚未规划完成时显示规划路线，到达后保留到选中取消或目标改变。迟到的旧指令错误不会清除新目标。点击另一只自家宠物会切换；点击邻居宠物不允许操作。单指拖动地图保留选中，拖动松手不发送移动指令。双指缩放、摇杆控制、地图定位、选址、打开设置或退后台会清除选中、目标标记及操作面板；宠物指令和同步刷新保留选中。乐园入口与场景页面单独禁用文字长按选中和复制，不影响长按摇杆和双指缩放。

宠物到达后停留三秒，再在当前区域自由活动；院内不出院，院外不进入任何庭院，手动指令仍可从院门进出。所有宠物均显示名字，重叠时错开。只有点击“跟随宠物”才跟随。手动缩放的值保存在本机；角色移动、回角色、回家、地图中心、尺寸变化、选址、重建场景和重进均保持该值，只有双指手动缩放能再次改变。旧“全景”按钮改为“地图中心”，仅居中，不改变缩放；完整地面可通过双指缩小查看，缩小下限随地面宽高计算。

加入常住小区后，点击“选择宅基地”或“调整庭院”，点击处就是别墅中心，预览中心十字、112×112 米围栏边框、别墅和院门后，再确认保存。预览与保存使用同一精确坐标，不再吸附到格子中心，保存时视角保持不动。新庭院为 112×112 米，已有 48/72 米庭院保留原尺寸，通过重新确认选址可升级，避免自动扩大后占到邻居或超出地图。服务端检查完整占地范围与邻居之间的四米间距，搬迁失败保留原庭院，成功后原位置腾空。

目前临时开放同小区内重新选址，每人仍只有一处庭院，迁居前必须先拆除旧庭院。需要恢复锁定时，在 api 云函数环境变量设置 PLAYGROUND_ALLOW_RELOCATION=false，重新进入乐园后生效；删除该变量或设为 true 可重新开放。已保存位置不会因开关变化而丢失，原庭院保留；拆除后才可迁入其他小区。

小区由名称、地址、城市和区县共同识别。同一地点需要选择地图中的同一小区条目，避免名称或地址差异导致划入不同场景。

车辆的使用、素材上传和部署说明见 [庭院车辆](playground-vehicles.md)。

## 新增庭院素材

选择宠物后可点“调整宠物大小”，每只宠物独立设置为默认大小的 50%～200%。滑动时即时预览，松手后调用 playground.setPetScale 写入该宠物的 playgroundScale，重新进入从 getOverview 恢复；保存失败回退到上次保存的大小。“恢复默认”保存为 100%。名字高度随模型大小调整，大小调节只改变外观，不改变位置、行走速度或寻路碰撞范围。服务端校验范围和归属，无需新增集合或索引。

喷泉使用同一云存储目录中的 pq/pq1.png～pq/pq6.png，按八帧/秒循环。dog_eat.png、cat_eat.png、dog_wo.png、cat_wo.png 与 house.png 位于同一 baseImage 目录。石板主路连接别墅和院门，支路通往猫狗用品与喷泉；树木、绿植和用品按实际庭院尺寸排列，碰撞区域与摆放一致。新增素材在基础庭院显示后后台加载，单张装饰加载失败不会阻止进入场景。

## 绘制与加载

草地从上传图片内部提取纹理，通过镜像平铺消除菱形泥土边缘与棋盘格背景。其余素材在离屏画布中按边缘连通区域去除浅色背景；保留原始文件。栅栏使用与地图相同的坐标绘制立柱和横梁，代替错位的整院栅栏切图，正面留出六米入口，门扇朝内打开。

近景按可视范围加载 112×112 米区域，离开后释放远处区域，最多四个并发请求。草地只绘制当前视口覆盖的地面；首次只加载草地和当前猫狗素材，遇到庭院才加载房屋和装饰。全景改为按小区分页读取庭院坐标并绘制聚合标记，避免按整张大草地逐块请求；放大后恢复附近庭院细节。寻路只针对目的地附近区域，避免为整张大地图建立寻路网格。加载失败时不允许在未知区域确认选址或规划行走。视角保留在客户端；角色位置、宠物运动路线、庭院和占地规则由服务端管理。共享场景另按游标分页同步角色与宠物。

本地测试验证逻辑与浏览器 Canvas 绘制；真机上的云存储权限、网络加载和微信 Canvas 兼容性需要部署后验收。
