# 2D 宠物乐园

## 上线步骤

1. 上传并部署 `cloudfunctions/api`，创建 `pet_playground_plots` 集合（或由后台数据库初始化创建）。该集合设为仅云函数可访问，客户端禁止直接读写。无需新增自定义索引。
2. 云存储保留 `packagePlayground/2d/baseImage/` 下原有 PNG 文件，名称与 `baseImage/` 中一致。加载器直接下载云文件，缓存本次小程序进程内的临时路径，不依赖包内图片。更新同名云文件后需重启小程序以清除进程缓存。
3. 管理端 → 系统设置 → 宠物乐园地面，配置宽高并保存。默认 2240×2240 米，支持 224～11200 米的整数。重新进入乐园生效；不能缩小到已有房屋之外。

## 使用

单指拖动，双指缩放，点击草地让选中的宠物行走。宠物停止后等待下一次指令。点击名字切换宠物，“跟随宠物”把视角移回宠物，“回到家园”浏览自己的房子。

加入常住小区后，点击“选择宅基地”，在未占用草地上预览 48×48 米庭院，点击“永久安置”后再次确认。选址永久保存在数据库，每人只有一块，不能搬迁或通过更换小区重复领取。认领后自动生成中心别墅、通往院门的石板路、树木、花丛和路灯；其余地方保持草地。

小区由名称、地址、城市和区县共同识别。同一地点需要选择地图中的同一小区条目，避免名称或地址差异导致划入不同场景。

## 绘制与加载

草地从上传图片内部提取纹理，通过镜像平铺消除菱形泥土边缘与棋盘格背景。其余素材在离屏画布中按边缘连通区域去除浅色背景；保留原始文件。栅栏使用与地图相同的坐标绘制立柱和横梁，代替错位的整院栅栏切图，正面留出六米入口，门扇朝内打开。

场景按可视范围加载 112×112 米区域，离开后释放远处区域，最多四个并发请求。草地只绘制当前视口覆盖的地面；首次只加载草地和当前猫狗素材，遇到庭院才加载房屋和装饰。寻路只针对目的地附近区域，避免为整张大地图建立寻路网格。加载失败时不允许在未知区域确认选址或规划行走。宠物运动和视角保留在客户端，房屋位置和占地规则由服务端管理。

本地测试验证逻辑与浏览器 Canvas 绘制；真机上的云存储权限、网络加载和微信 Canvas 兼容性需要部署后验收。
