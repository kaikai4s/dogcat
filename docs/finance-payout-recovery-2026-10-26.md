# 提现与保证金退还修复

## 排查结果

- 保证金原来只有审批与人工确认退款：审批事务将状态改为 `refund_approved`，并未请求微信原路退款接口。“审核通过，待实际退款”符合旧实现，但不符合自动退款需求。
- 微信提现提交异常会保持 `transferring / unknown`，收益和转账额度仍被占用。原后台仅在 `approved` 和 `transfer_failed` 提供重试按钮，`unknown` 只有查单，难以继续处理。
- 提现审批只检查 `staffSupplies.transfer.enabled`，与实际微信转账配置读取器支持的环境变量、历史 `payment.transfer` 配置不同，可能审批成功却没有发起转账。
- 截图“记录不存在”保存在 `lastTransferError`，对应转账提交/查单接口错误，旧代码未保存微信错误码。仅凭这句话无法判断线上原单是否已受理、原商户是否发生过变化。本次没有访问线上账单或执行真实资金操作。
- 后续确认实际错误码为 `NOT_FOUND`。微信[商户单号查询转账单官方文档](https://pay.weixin.qq.com/doc/v3/merchant/4012716437)明确列出 `404 NOT_FOUND / 记录不存在 / 查询的转账单不存在`。原恢复逻辑只判断 `RESOURCE_NOT_EXISTS`，漏掉该接口的正式错误码，导致查询报错后无法进入同号补交；现已在该转账查询分支同时兼容两者，未改动退款接口的错误码规则。
- 最新截图显示该笔为 **0.07 元**，微信返回 `INVALID_REQUEST / 超过单笔转账上下限，核实产品设置是否准确`。微信[设置转账额度官方文档](https://pay.weixin.qq.com/doc/v3/merchant/4013747667)规定单笔最低 **0.10 元**；项目原先允许 0.01 元，且后台将实际拒绝原因归为“转账结果待确认”，掩盖了金额限制。此前使用 0.07 元模拟成功的测试没有体现真实网关限制，已修正。

## 修复后的行为

微信提现审批统一调用转账服务，由该服务读取并验证配置。配置不完整、提交失败会同时返回“审核已通过，转账待处理”和错误原因，保留审核结果。微信错误码与提示保存在单据上；`unknown` 或查单返回不存在时提供“核对原单并安全重试”。该转账查询明确返回 `NOT_FOUND` 或兼容的 `RESOURCE_NOT_EXISTS`，且原商户信息完整时，才复用原转账单号提交；超时、解析失败和其他查询错误不会另建单或释放收益。成功后清除旧错误。

宠托师与用户资产提现的申请、审核和实际提交都执行微信最低 0.10 元限制；后台结清可跳过业务提现门槛，但仍须达到微信最低金额。按50条收益分批时，尽量移动完整收益记录，避免最后一批低于最低金额；不能组合时保留小额余额并明确提示。不会提高提现金额或拆改宠托师原收益。

已审批的历史小额单改为“查原单并退回余额合并提现”。服务端只向原商户查询原单号，明确返回上述不存在错误、且金额/原商户/AppID/尝试次数仍匹配时，事务释放收益与额度，保留原提现记录；不会伪造转账失败或到账。原单查询超时、原商户信息缺失或变化时保留占用；查到原单则同步结果，不能退回余额。该入口复用“释放失败提现”权限，重复点击不会重复释放。待审核小额单直接驳回后合并申请。

退出时全部剩余收益仍不足0.10元，可从“宠托师管理 → 小额尾款人工结清”建立待审核人工付款单。只有无其他待结算、冻结或未完成提现时才允许建立；财务审核后，实际付款并登记真实凭证号才计为已结清，保留双人复核和完整流水。该入口不向微信接口提交不足最低金额的转账，不把生成结清单视为实际到账。使用说明见[退出尾款](staff-onboarding-and-settlement-2026-10-26.md)。

后台查询/重试接口返回实际微信状态、错误和错误码。界面明确显示网关拒绝；只有实际 `WAIT_USER_CONFIRM` 状态才提示收款人确认，不再把拒绝错误统一提示为待确认。

后续检查补充修复：分批结清遇到微信拒绝或其他转账错误时，立即停止后续批次，展示实际错误码并保留原批次续办信息；不再误报发起成功。提交前同时核对提现的元金额与分金额，释放收益前复核关联收益合计，历史金额不一致时保留原记录并要求核账。定时查单的迟到异常只更新仍在处理的记录，不能覆盖已到账或已退回的最终状态。已到账、已退回和人工结清记录不再显示残留的微信确认收款按钮。

微信保证金审批后调用 `/v3/refund/domestic/refunds`，使用原交易号或原支付商户单号，固定退款单号，按分校验原支付总额和批准可退额。退款处理中保留原余额，只有经查询/提交返回明确 `SUCCESS` 且退款单、金额、原支付凭证一致后，才事务更新余额、退款事件、资金流水和退出进度。并发查单及迟到错误不会重复扣账或回退成功状态。非微信支付走有凭证的人工退款。

五分钟定时任务补发历史 `refund_approved` 记录、核对 `refunding` 记录，以及在收益/其他保证金结清后完成退出。任务按最后查询时间轮转，有时间预算，单笔失败不会阻塞其他记录；异常退款 `CLOSED / ABNORMAL` 保留原单待核对。

## 发布

1. 部署 `cloudfunctions/api`，保留 `expireOrders` 五分钟定时触发器。
2. 核对真实微信支付配置、`payment.mode = wechat`、退款开关和商家转账开关/场景配置。保证金使用原支付退款，不使用商家佣金转账。
3. 检查/创建以下 `staff_deposits` 非唯一复合索引，字段均升序：`status, refundLastCheckedAt, _id`；`refundStatus, refundExitPending, refundLastCheckedAt, _id`。原支付查询使用 `payments(orderId, targetType)`。
4. 更新小程序。普通管理员如需手动同步，增加“同步保证金原路退款”权限（`admin.syncDepositRefund`）；超级管理员可直接使用。
5. 已审批保证金无需重新提交申请，后台同步按钮或定时任务会继续处理。对历史人工转过款但未登记凭证的单据，应先核对真实账单并如实补记，避免自动补发时混淆原人工退款。

当前修改仅在本地，未部署或进行实款转账。部署本次 `api` 云函数并更新小程序后，金额符合限制的原提现单可通过“核对原单并安全重试”或五分钟定时对账恢复。截图中的 0.07 元单应使用“查原单并退回余额合并提现”，确认原单不存在并退回后，可与其他 0.28 元收益合并为 0.35 元重新申请；仍须满足后台配置的业务提现门槛。最终以微信真实转账状态及实际到账为准。
