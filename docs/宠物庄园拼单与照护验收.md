# 宠物庄园拼单与照护

## 用户入口

- 服务首页：所属小区有可参团拼单或本人已有拼单时显示提醒；停留页面时每30秒刷新。
- 宠物庄园：快捷功能中的“我的拼单／邻居拼单”，以及“居委会·拼单”面板。面板直接列出本人的拼单订单和可参与拼单。
- 拼单提交后仍进入真实订单详情；“我的拼单”可持续查看户数、截止状态与自己的订单。
- 角色走近已认证宠托师的别墅院门，可查看完整个性名片、近期服务类别与日期、评价，或发起指定预约。预约复用既有排班、日期例外、接单截止日、服务范围和冲突检查。
- 角色走近自己或邻居的宠物，可查看公开照护记录。公开内容只有宠物称呼、照护类别、日期和照护中状态。

## 拼单规则

1. 地点取本人资料中的所属小区，后台再次验证小区身份，并使用已保存的小区坐标。楼栋、门牌只存在本人的订单中。
2. 每个用户、同一规范化楼栋门牌在同一拼单内只计一户。不同小区不能参团；参团服务日期与每日开始时间应相同。
3. 默认3户成团，免上门费后按8.8折计算，不叠加优惠券。按分进行四舍五入，最低支付1分。
4. 未成团不允许支付；达到户数时，在创建订单的同一事务中统一更新参与订单优惠。优惠规则保留发起时快照。
5. 成团后优惠锁定，不因其他成员后来取消而撤回；取消的订单不计入当前参与户数。新加入者仍按该团快照获得优惠。
6. 默认募集12小时，并至少在服务开始前2小时截止；成团参与者有30分钟支付时间。募集截止后不能加入，未成团订单按既有超时任务关闭。
7. 拼单目前通过公开订单流程派单；指定宠托师预约继续使用原指定预约流程。

## 后台统一配置

入口：后台首页“宠物庄园” → “庄园规则与配置”。形象定制、庭院植物、建筑与土地也收拢在此板块。

- 拼单：开关、成团户数、折扣比例、上门费减免、募集小时数。
- 地面：庄园宽高，保留已有占地边界保护。
- 猫、狗分别配置：精力／饱腹／水分每小时下降速度，休息／进食／饮水每秒恢复速度，尿意／便意每小时增长，院外排泄阈值和等待秒数。
- 默认尿意20且院外等待45秒后嘘嘘；便意40且院外等待120秒后便便。任一数值到100时原地排泄，动作持续3秒。
- 保存平台规则仍需主管理员权限；后台服务端校验参数范围。

## 服务与隐私

庄园里的照护角色根据真实订单的 `in_service` 状态出现。照料服务表现为入院清理、添粮和恢复宠物状态；遛狗服务只带该订单预约的狗沿可通行路线出院散步，订单结束后走回庭院。庄园动作不会伪造真实服务打卡或完成订单。

服务中的预约宠物不接受手动跟随、移动等冲突指令；退出并重新进入庄园仍保留照护与返家过程。服务角色使用已有角色素材，已有可用专属形象时沿用宠托师形象。

公开宠物记录不返回订单号、客户或宠托师身份、地址、门牌、联系方式、门锁资料、打卡照片或自由填写备注。公开宠托师服务历史也只返回服务类别、日期与宠物数量；医疗项目统一为“日常照护”。完整打卡信息继续走原有授权订单入口。

## 部署与人工验收

1. 部署更新后的 `api` 云函数与小程序页面。
2. 初始化新增集合 `pet_playground_groups`，应用同名数据库权限规则（客户端禁止直接读写），执行现有数据库初始化流程以创建新增索引。已有业务数据不需要迁移。
3. 新增索引包括小区拼单、客户进行中服务、宠托师已完成服务。索引未就绪前不进行线上验收。
4. 用同小区至少3个账号发起、参团、成团付款；异小区账号不能看到或加入该团。检查庄园面板、服务首页、订单详情三处入口，以及未成团付款拦截。
5. 认证宠托师的别墅出现标识，撤销审核后标识消失；院门入口打开同一份个性名片，并检查排班外、休息日、截止日期之后无法预约。
6. 用真实服务开始／完成操作观察照护角色进院、只带预约狗出院、牵引散步、完单回院；中途重进庄园检查状态延续。
7. 用他人角色走近宠物查看记录，检查公开响应中没有照片、备注、订单号、联系方式或住宅细节。

本地自动化覆盖拼单真实接口与事务、身份与优惠校验、认证标识撤销、遛狗返家与重进场景、猫狗参数同步、附近交互及公开记录隐私。微信开发者工具与真机视觉效果需在部署后按上述步骤验收。

## 小区入住人数统计

- “已入住”按当前小区已有有效主住宅的不同住户统计，同一住户只计 1 人，包含离线、尚未进入庄园或没有宠物的住户。
- 独立扩建地块、空地、小木屋、公共建筑、访客、宠物与照护角色不增加人数；已拆除地块不参与统计和地图展示。住宅标识由服务端提供，前端按公开住户标识去重，不公开用户 openid。
- 统计读取全部场景分页，与当前视野和在线人数无关；新入住、迁居、拆除通过场景实时同步更新，较旧快照不能覆盖新迁出状态。
- 认证宠托师标识仅挂在有效主住宅上；扩建地块不再被误认为本人住宅或重复挂载认证标识。
- 人工验收：同小区两个账号各建主住宅，人数为 2；其中一个账号离线或扩建，仍为 2；拆除其庭院后为 1。切换到其他小区时核对该小区自己的住户数量。
- 本次针对性测试 68 项、完整回归测试 1548 项全部通过，JavaScript 语法和图标检查通过；尚未部署云函数或进行微信真机验收。


## Bug 复查与界面优化（2026-10-20）

- 拼单列表与事务统一排除支付超时成员，保留取消、超时的本人订单入口，避免户数和实际可付款状态不一致。
- 首页等待异步登录结果后才查询拼单，刷新时同步拼单信息；退出页面清理轮询，账号变化和旧响应不能覆盖当前数据。
- 下单底栏、数字价格和明细统一展示成团优惠后预估价，明确“成团后付款”；旧试算响应不会覆盖新选择。
- 服务按订单及当日服务标识维护独立照护角色，支持同一住户不同宠物同时接受服务。新的一天、新的宠托师或场景几何变化均会重建照护流程，返家等待宠物真实到达。
- 小区宠托师名片分页查找，避免被全站前十条截断，并使用公开个性名称与真实评分字段。
- 拼单页加入成团进度、付款截止时间、状态卡片、错误重试与隐私提示；后台拆分日常消耗、照护恢复、院外排泄，支持猫狗切换、规则试算与固定保存栏。
- 庄园院门预约合并为名片卡片，公开照护记录改为可滚动面板，仅显示白名单信息。
- 完整回归测试 1544 项通过。拼单页与后台配置页使用现有模板、样式及模拟数据进行了 320px / 390px 静态渲染，未发现横向溢出；静态预览不能替代微信开发者工具及真机交互验收。
