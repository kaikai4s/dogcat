# 退款账务及服务授权修复

## 退款与收益

真实微信退款采用两个阶段：预占退款额度时写入 `earningsAccountingVersion: 2`，并通过收益的 `pendingRefundIds`、订单的 `pendingEarningRefundIds` 阻止相关收益提现；此时不扣减收益、不退还已使用优惠券。微信确认成功后，在同一事务中冲减收益、清除对应冻结、更新退款结果，全额成功才退券。终态失败只解除对应冻结。其他仍在处理的退款冻结会保留。

收益查询、写入和财务日志失败会中断事务。若网关已成功、本地写入失败，退款单继续保持 processing，定时回查使用原退款号再次结算，避免重复扣减。完单与退款竞争时，新收益继承处理中冻结；退款已成功的迟到完单按实际退款额计算收益。模拟退款保留原本的模拟处理口径，不作为真实支付到账证明。

相关收益已在待审提现中时，退款处理中阻止审批；退款成功后原子驳回原申请，释放该申请的所有收益，再仅按本次退款比例扣减对应订单收益。原提现申请金额不改写，员工可按剩余收益重新申请。已审批或已产生转账意图的提现必须先核实处理，不允许退款同时改写该收益账本。

旧版本已经扣减的 processing 退款没有版本字段，回查时保留原账务口径，避免重复扣减。旧版本失败退款造成的收益扣减、提前退券，以及已损坏的提现关联不能仅凭当前余额推断恢复；需结合退款明细、收益和真实付款凭证核对。本次代码不连接生产数据库、不修改历史资金记录。

## 服务与纠纷访问

提前开始申请和批准绑定员工、接单时间、场次编号及场次开始时间。改派、重新接单或进入后续场次后，原批准失效；解锁窗口也使用同样的绑定。缺少这些字段的旧授权不再允许提前开始，需要员工重新申请，按原预约时间开始不受影响。

纠纷参与权限只允许非管理员读取必要订单摘要；电话、家庭地址、安防字段和实时位置通过原订单权限入口获取。管理员纠纷详情也不返回密码密文。保存方案不能直接结案，结案须走原收益处理流程，并在事务中防止并发重新打开已结案纠纷。

新人券资格检查遍历用户全部服务及商城订单，查询失败中断发券。多日服务结束日期增加实际日历校验，拒绝不存在的日期。
